# Птица Пицца — правила для агентов

Браузерная 3D-игра (three.js, Vite, без фреймворков) про доставку пиццы по закрытому городу Солнечному (карта — из данных
настоящего Северска, внутри кода id `seversk`; игроку — только «Солнечный»).
Автор — геймдизайнер, код не читает: правила мира живут в доках словами и цифрами.

## Где что

- **Что делать дальше и статус по трекам** (Стим, наполнение мира, игра, продвижение, телефоны) —
  треки в начале [docs/IDEAS.md](docs/IDEAS.md). Спросили «над чем работаем?» — отвечать по нему; шаг
  сделан — обновить статус и журнал там.
- Правила мира: [docs/CAREER.md](docs/CAREER.md) (смена, деньги, машины, сердца, карта),
  [docs/ORDERS.md](docs/ORDERS.md) (заказы, клиенты, штрафы), [docs/CONTENT.md](docs/CONTENT.md)
  (детская и взрослая версии). План работ — [docs/IDEAS.md](docs/IDEAS.md), куда идём —
  [docs/DIRECTION.md](docs/DIRECTION.md). Как проверять — [docs/AGENTS.md](docs/AGENTS.md).
- Редактор города (`npm run editor`) — пометки автора на карте лежат в `src/maps/seversk/notes.json`
  (открытые — `done: false`; сделал — `done: true`), его правки предметов — `edits.json` ([docs/SANDBOX.md](docs/SANDBOX.md)).
- Музыка — [docs/MUSIC.md](docs/MUSIC.md) (файлы — в `public/music`).
- Звуки: имена файлов и что где звучит — [docs/SOUNDS.md](docs/SOUNDS.md) (файлы — в `public/sfx`).
- Словарь терминов автора (сессия, смена, событие, хад…) — [docs/TERMS.md](docs/TERMS.md); новое
  неочевидное слово автора — сразу туда.
- Код: `src/game/*.js`. `game.js` огромный (13 тыс. строк) — не читать целиком, грепать.
  Числа экономики — `econ.js`, заказы — `orders.js` / `orders.config.js`, смена — `career.js`.
- Отладка: с `?debug` (и всегда в dev) есть `window.__dlv` — состояние и ручки игры.
- Ошибки и зависания у игрока — журнал `src/platform/crashlog.js`, файл и как читать — [docs/CRASHES.md](docs/CRASHES.md).
  Новый шаг мира в кадре — через `CL.step('имя', fn, dt)` (предохранитель).

## Правила

- **Автор пишет, что добавить в игру** — сначала записать в docs/IDEAS.md, сгруппировать и
  отсортировать (важность × размер), показать автору группы и порядок и спросить «ок или не ок?».
  В работу — только после «ок» (или если в том же сообщении сказано «начинай»).
- **Порядок работы** (автор, 08.10.2026): **сначала баги**, потом то, что делает **понятнее, как
  играть** (интерфейс, подсказки, что вводит в заблуждение), и только потом новое и красивое.
- **Цикл захода** (автор, 08.10.2026): автор даёт потолок недельного лимита и «ок» на приоритеты →
  главный агент раздаёт работу субагентам, следит за общим процентом недели (`get_usage`; растёт и
  от других сессий автора) → закончил — коммит и **релиз сам, без вопроса**. Правки, которые нашли
  наши же ревью-агенты (например, разбор интерфейса), главный агент сам приоритизирует в IDEAS.md и
  берёт в работу без «ок».
- **Субагентов — не больше 6 одновременно** (автор, 09.10.2026). Потолок лимита — по проценту
  «Weekly · all models» во вкладке лимитов: дошли до потолка — стоп, **релиз — до этого**.
- **Изменил правило — обнови док** (CAREER.md / ORDERS.md) словами и цифрами, а пункт — из
  IDEAS.md в IDEAS-ARCHIVE.md.
- **План — только несделанное** (автор, 10.10.2026): в [docs/IDEAS.md](docs/IDEAS.md) нет ничего
  сделанного — ни `[x]`, ни «Сделано», ни журнала. Пункт сделан → в тот же заход убрать из IDEAS.md и
  перенести как есть, с датой, в [docs/IDEAS-ARCHIVE.md](docs/IDEAS-ARCHIVE.md); строка журнала — в
  конец архива. Вопросы автору — только в [docs/QUESTIONS.md](docs/QUESTIONS.md) (в IDEAS.md — одна
  ссылка); ответил — убрать вопрос оттуда, решение — в доки правил и архив.
- **После каждого захода работы — обнови план целиком**: «Сейчас главное» (что первое теперь),
  статус треков, «Что осталось» (сделанное — в архив, найденные баги — добавить), вопросы — в
  QUESTIONS.md, строка журнала — в архив. Делает главный агент перед коммитом и релизом.
- **Новая система — в свой файл** (`hits.js`, `junk.js`, `fauna.js`, `mafia.js`, `chat.js`,
  `shiftend.js` — образцы); в `game.js` — только подключение и точечные хуки.
- **Основная версия — взрослая (Стим, 18+).** Детскую (Яндекс, `--mode yandex` / `?kids`) **не
  проверять и не собирать без явной просьбы автора** — Яндекс собираем по нужде. Но взрослое
  (кровь, мат, 18+) по-прежнему держать за флагом `ADULT`, чтобы детская сборка не сломалась.
- **Строки** — через `t` / `$t` / `N_` ([docs/I18N.md](docs/I18N.md)). Субагент пишет только
  ru (в коде) и en (`src/i18n/en.json`); остальные 12 языков и `npm run i18n:extract` — один проход
  в конце блока.
- **Git не трогать** субагентам: ни commit, ни stash, ни checkout/reset. Коммитит и пушит главный
  агент — только от личного аккаунта `ndrwbv` (ssh `github-personal`), сразу в `main`, без PR.
- Деньги в карьере умножены (`MONEY_K` в econ.js): пиши суммы так, как их видит игрок.
- **Релиз — всегда со списком «что нового».** Запускает главный агент: `gh workflow run release.yml
  -R ndrwbv/bird-delivery -f bump=patch|minor|major -f notes="…"`. В `notes` — что добавлено и
  исправлено именно в этом релизе (с прошлого тега: `git log <прошлый тег>..HEAD`), словами для
  игрока, коротким списком по-русски, без имён файлов. Без `notes` релиз не запускать.

## Как проверять — от дешёвого к дорогому

1. `npx vite build --mode web --outDir <своя временная папка>` — собирается ли.
2. `npm run probe -- --js="..."` — игра без браузера, ответ числами (docs/AGENTS.md). Это основной
   способ: числа из `__dlv` вместо скриншотов.
3. `npm run probe -- ... --shot=out.png --scale=0.5` — только когда надо увидеть глазами.
4. Браузер — в крайнем случае: только тот слот, что выдал главный агент в задании
   (`agent-1` … `agent-8` в `.claude/launch.json`, порты 5201—5208, без автоперезагрузки — свежий
   код по F5). Слот не выдан — браузер не открывать. Скрипты — только в своей вкладке (проверь порт).
5. Перед отчётом — `npm run check`.
6. **Проверки — без звука** (автор, 09.10.2026): probe/perf/tour глушат Электрон (`mute-audio`),
   в браузере — только с `?mute`. Звук у автора во время работы агентов играть не должен.
