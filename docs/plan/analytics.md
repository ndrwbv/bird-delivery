<details><summary><b>Решения</b> (что уже решено и почему)</summary>

**Где хранить** (автор 18.10: «не Cloudflare — либо наш VDS, который уже есть, либо облачная функция в Яндексе»):

| | что | бесплатно | плюсы | минусы |
|---|---|---|---|---|
| **А (совет)** | **свой VDS автора**: маленький приёмник (Node, один файл) + база SQLite, за nginx с HTTPS | уже оплачен | всё наше; агент читает базу по ssh и пишет сводку; данные в России (152-ФЗ); никаких лимитов вызовов | нужен домен/поддомен с HTTPS (Let's Encrypt), автозапуск (systemd), бэкап файла базы |
| Б | Yandex Cloud Functions + YDB (serverless) | free tier ([Yandex Cloud](https://yandex.cloud/ru/docs/billing/concepts/serverless-free-tier), 18.10): функции — 1 млн вызовов и ~10 ГБ×час в месяц; YDB serverless — 1 млн операций и 1 ГБ в месяц. Пачка событий раз в минуту → ~16 тыс. часов игры в месяц бесплатно | без своего сервера: не падает, не надо обновлять и бэкапить; данные в России; растёт само | кабинет Yandex Cloud и платёжный аккаунт с картой (даже для бесплатного уровня); сервисный аккаунт и ключ для агента (`yc` CLI, ключ — в `*.local`); больше движущихся частей (функция + API Gateway/URL + YDB); при росте — платно |

**План при варианте А:** 1) автор даёт доступ к VDS (ssh-подключение в Claude Desktop или ключ; ОС, есть ли nginx и
домен) — руками; 2) приёмник `tools/telemetry/` (Node + SQLite, systemd, nginx-путь `/t`), события пачками раз в
30—60 с и в конце сессии, без влияния на кадр — S; 3) события в игре (`telemetry.js`, хуки в смене, режиссёре,
crashlog) + выключатель в настройках + строка в политике конфиденциальности Стима — M; 4) `npm run stats` — агент
тянет базу по ssh и пишет сводку словами в `docs/STATS.md` — M; 5) после каждого релиза — сводка автору.

**Сделано 18.10 — второй заход** (падения со следующего запуска, видеокарта, прогресс и покупки, воронка новичка, тепловая карта 100 м, экраны, настройки, медленные шаги, загрузка; текст политики в игре — «что собираем ▸», privacy.html из privacytext.js). Было в плане: **Дальше — чего не хватает** (автор 18.10: «добавляй больше логов в первую очередь»; разбор 18.10, вопрос автора «краши логируешь? девайс? игровые точки?»):
1. **Падение целиком — при следующем запуске** (S): оболочка Стима (electron/main.cjs) отдаёт игре записи своего файла `crash-*.log` (падение процесса, «не отвечает»), игра шлёт их событием `crash_prev`; плюс «прошлый запуск кончился посреди смены без выхода» — видно падения и в браузере; потеря контекста WebGL — в журнал.
2. **Модель видеокарты** (S): `WEBGL_debug_renderer_info` — название GPU в `session_start` (Дека, слабые ноутбуки, телефоны).
3. **Прогресс и покупки** (S): открытие районов, уровень курьера, покупки машин и улучшений, копилка на начало смены.
4. **Где бросают обучение** (S): шаги первой смены и подсказок — воронка новичка.
5. **Где разбиваются и гибнут** (S): клетка ~100 м (грубая сетка) у взрыва, срыва, сильного удара — тепловая карта сложных мест.

**Другие варианты** (рассмотрены 18.10, запасные):

| | что | бесплатно | плюсы | минусы | решение |
|---|---|---|---|---|---|
| В | Cloudflare Workers + D1 | 100 тыс. запросов в день, 5 ГБ | своё, без SDK, агент читает через `wrangler` | чужой сервис за рубежом | **отклонено автором 18.10** |
| Г | PostHog Cloud | 1 млн событий в месяц | готовые графики, воронки, записи сессий | чужой SDK ~50 КБ, сервера США/ЕС, из России нестабильно | запасной |
| Д | Sentry (только ошибки) | 5 тыс. ошибок в месяц | лучший разбор падений (стек, версия, устройство) | ещё один сервис, доступность из России под вопросом | можно добавить к А для падений |
| Е | GameAnalytics | бесплатно | сделан для игр (сессии, прогресс, ошибки) | SDK, свой кабинет, агенту читать неудобно | запасной |
| Ж | Umami / Plausible на своём VDS | бесплатно (свой сервер) | готовая панель посещений | заточены под сайты, не под игровые события | не подходит |
| З | только локальный журнал (`crashlog.js`) + кнопка «отправить отчёт» | бесплатно | ничего не уходит без спроса | данных мало, только от тех, кто нажмёт | дополнение к А |

**Условия:** Стим требует написать в описании/политике, что игра собирает анонимную статистику; Яндекс (детская) —
не собирать. Персональные данные россиян (152-ФЗ) не храним — только анонимный номер установки.

</details>

## Трек 12. Аналитика: что происходит у игроков

**Статус:** заведён 18.10.2026 (автор: «трек — аналитика игры: чтобы ты её смотрел и понимал, сколько длится игра,
какие баги, что ломается, какие механизмы включаются; логи; подумай, что бесплатного использовать или поднять своё»).
**Сделано 18.10 (вариант Б, Яндекс):** каталог `bird-pizza`, база YDB `bird-stats` (таблица `events`, строки старше года стираются), функция-приёмник `bird-ingest`, `src/game/telemetry.js` (сессии, смены, механики и исходы, ошибки, скорость раз в минуту), выключатель «анонимная статистика» в настройках, `npm run stats` → `docs/STATS.md`; как устроено — [ANALYTICS.md](ANALYTICS.md). **Осталось:** автору — текст «Анонимная статистика» из STEAM-COMPLIANCE.md в описание Стима и страницу политики в Steamworks; агенту — сводка после каждого релиза, когда пойдут данные игроков. Решение:  — личный профиль `yc --profile personal` (облако `cloud-ndrwbv`; профиль `default` — рабочий, не трогать), отдельный каталог `bird-pizza`; функции `arbuz-api`, `digest-reactions` в каталоге `default` — чужие проекты автора, не трогать.

**Что собираем** (анонимно: случайный номер установки, без имени, почты, IP в хранилище; выключатель в настройках;
в детской версии — выключено совсем):
- сессия: сколько длится игра, сколько смен за заход, где бросил (меню, гараж, посреди смены);
- смена: длина, заказы, опоздания, сердца, взрывы, воскрешения, деньги, район, сезон, праздник, вид камеры;
- механики: какие события включились (мини-игры, поручения, сценки, герои, гопники, перекрытия, полёт, трамплины)
  и что игрок с ними сделал (согласился / отказался / провалил);
- ошибки: журнал падений и зависаний (`crashlog.js` уже пишет локально) — отправлять;
- скорость: устройство (компьютер / Дека / телефон), качество графики, кадр p50 / p95, провалы > 50 мс, память.

</details>
