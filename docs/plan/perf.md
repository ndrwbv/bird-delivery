<details><summary><b>17</b> · Готовить город заранее и загружать только нужные участки · <b>XL</b></summary>

**Уточнение 01.11.2026, автор:** очень долгие первый запуск и загрузка при смене профиля; проанализировать устройство игры и подготовить спеку следующему агенту. **Задание следующему агенту:** [спецификация загрузки](../specs/loading.md) — причины, свежие измерения, миграция сохранений, контракты участков, этапы и приёмка. Она уточняет порядок ниже: №12 → 17ж → 17а → 17б → 17в → 17г → 17д → 17е, после нового первого пакета правок автора в IDEAS.md. В этом анализе игровой код не изменён. Исследовательские прогоны CPU ×3 дали меню 14,7 с / окончание очереди 105,0 с; другой сценарий раннего входа в смену — 102,3 с после нажатия, при готовых только 32 из 1776 участков земли. Это разные сценарии на macOS, не три повтора и не физическая Deck. [Отчёты](../measurements/loading-2026-11-01/README.md).

**Запрос автора, 26.10.2026:** «Придумай как строить город эффективно. Город большой а игрок не поедет сразу … из одного в другой конец». Приоритет: ускорение запуска и устранение остановок при езде — перед новым наполнением мира. Это проект следующего изменения, не описание уже выпущенной возможности. №15 уже загружает только подробную землю и бордюры рядом; №16 позволяет выбрать размер кадра, но не ускоряет вычисление города.

**Что выяснено по коду, 26.10:** `buildCity` в `game.js` всё ещё сразу вызывает общие `osmGround`, `osmRoads`, `osmBuildings`; затем очередь обходит весь город для дворов, подъездов, парковок, реквизита и других слоёв. Очистка контуров и физическая опора земли пока глобальные. Этапы `mesh`, `upload`, `shaders` обходят подготовленную сцену. `landstream.js` строит участки по 256 м (640 м до старта / запрос до 832 м), но не выгружает готовые участки. `cull.js` обычно отсоединяет невидимые меши от сцены и хранит ссылки: скрытие не равно освобождению памяти. У леса уже есть собственные клетки и `dropCell` — этот механизм учитывать, не дублировать второй системой. Новых замеров в этом проектном заходе не было; прежние 28 с на рабочем компьютере / 85 с при CPU ×3 — только контрольная база №15, не обещание нового результата.

**Решение — предложено агентом 26.10:** дорогую неизменную часть города готовить один раз при сборке релиза. Во время игры читать готовые участки и постепенно передавать их видеокарте. Территорию делить регулярной сеткой по 256 м, совместимой с землёй, а не административными районами: границы районов слишком крупные и неудобны для поворотов и соседних улиц. Район определяет доступность заказов, но не границу подгрузки.

**Слои данных:**

| Что | Когда нужно |
|---|---|
| Каталог адресов, пиццерий и районов, дорожный граф, связи подъездов | Компактные данные для выбора смены, заказа и маршрута; наличие адреса не требует меша дома. Объём и время чтения измерить. |
| Высоты, покрытия, неподвижные препятствия | Подготовленные данные; физика рядом и впереди должна быть готова до доступа машины. Перенос рисунка не меняет опору. Сначала сохранить существующие глобальные физические данные, но убрать их дорогой пересчёт при запуске. |
| Земля, дороги, дома, дворы, деревья, окна и реквизит | Готовые меши и таблицы экземпляров по участкам; общие материалы и шаблоны один раз. Не объединять весь город в один меш. |
| Машины, прохожие, разбитые предметы и события | Состояние отдельно от рисунка; постоянные ID, изменения поверх исходного участка. Миграция акторов между участками не должна создавать копии. |

**Старт и приоритет загрузки:**

1. Взять точное место появления из сохранения/выбранной пиццерии. Загрузить машину, основные материалы, опору и видимый город вокруг неё. Исходный радиус 640 м сохраняет нынешнюю высокую дальность 490 м с запасом для камеры; сокращать его можно только после проверки реальной видимости. Полная земля и дома в видимой области обязательны; мелкие украшения могут догружаться вне поля зрения. Стартовая готовность должна зависеть от этого набора, а не от опустевшей очереди всего города.
2. После старта приоритет: безопасность под колёсами → видимое из камеры → соседние улицы во всех направлениях → впереди по скорости и направлению → ближайшая часть маршрута доставки. Навигатор повышает приоритет, но не единственный источник: игрок может свернуть или развернуться. Закрытый район, который виден через границу, всё равно должен иметь нужный рисунок.
3. Запас вперёд рассчитывать по измеренному p95 полного пути «чтение → распаковка → создание → загрузка в GPU», скорости машины и резерву. Начальная проба — ближайшие 2–3 участка впереди; окончательное расстояние определяется замером, не фиксированными «20 секундами». При разгоне запрос расширяется, при повороте устаревшие дальние задачи понижаются/отменяются. Уже видимые участки и необходимые стыки не отменять.
4. На основном потоке только короткие шаги и публикация готового участка. Диск/сеть и распаковка — отдельно; ограничить число одновременных запросов, байты ожидающих результатов и загрузку в GPU. Бюджет 0,5–1 мс на кадр — начальная цель, а не гарантия: один крупный шаг может превысить его, значит крупные операции надо дробить. Материалы прогреть на небольшом наборе представителей, а не на всём городе. При плохих кадрах отложить украшения; физическую готовность обеспечить заранее.
5. Позади держать запас для разворота. Начальные параметры для проверки: выгрузка дальше 1,5 км и после 30 с без использования, с отдельным пределом памяти и вытеснением давно неиспользуемого. Радиус выгрузки всегда больше радиуса загрузки — на границе ничего не дёргается. Перед освобождением сохранить изменения; освободить собственные геометрии, ссылки отсечения, маски и индексы. Общие материалы и шаблоны не освобождать, пока ими пользуются другие участки. Текущая ячейка, её физическое окружение и участники незавершённого взаимодействия закреплены в памяти.

**Подготовка при сборке:** сначала проба на самой дорогой земле: чистые контуры, опора, готовая геометрия и границы. Затем общий каталог и статические слои. Строитель может пройти весь город один раз в существующем порядке и разделить выход на участки: так не придётся сразу переписывать все зависимые генераторы и менять результат случайной генерации. Для больших пересекающих границу объектов — один владелец и ссылки соседей/область охвата; для поверхности — существующие правила стыков с полями соседей. Расположение и идентификаторы объектов должны совпасть с текущей картой и правками редактора. Новые независимые генераторы используют жребий по ID объекта/клетки и версии, не общий поток Math.random; порядок приезда игрока не меняет город.

Формат: небольшой манифест и бинарные блоки чисел/геометрии; размер транспортного файла подбирать отдельно от размера клетки, чтобы не получить тысячи мелких запросов. Часть общая для сезонов, часть — параметры и изменяемые диапазоны снега/листвы. Версия данных включает исходную карту, правки редактора, генераторы и формат. Steam читает из поставки, браузер — по требованию с кешем версии. Тёплый кеш не должен скрывать медленный первый запуск. Устаревшие данные не смешивать с новыми. Редактор/разработка сохраняют путь пересборки; генерация всей карты во время обычного запуска не должна незаметно становиться запасным путём при ошибке кеша.

**Не менять незаметно правила мира:** на первом этапе переносится неподвижный рисунок; движение, заказы, часы событий и адреса сохраняют существующую логику. Удалённую жизнь можно позже считать укрупнённо, но только с отдельной проверкой правил: это не обязательное условие быстрого старта. Нельзя при возврате восстанавливать сбитые заборы, дублировать автомобили, забывать события, терять правки редактора или менять места предметов. При переходе в другую пиццерию/телепорте сначала готовить место назначения под явным экраном загрузки; во время обычной езды такой экран не допускается. На ошибке чтения сохранять существующий сплошной рисунок и повторять запрос; не открывать машине область без гарантированной физики. Проверка быстрейшей машины и худшей загрузки обязательна до включения.

**Порядок внедрения:**

- **17б · Версионированные данные города в сборке релиза · M** — манифест, карта/правки/формат, каталог адресов и граф, готовая земля, проверка полноты поставки; отдельный путь разработки.

- **17г · Дома, дороги и дворы по участкам · L** — выделить данные из генераторов, сохранить глобальные зависимости, владельцев и стыки, подключать слои последовательно с замерами.
- **17д · Выгрузка и восстановление посещённых мест · M** — освобождение памяти, закрепление взаимодействий, постоянные ID и изменения участка, безопасность общих ресурсов.

Память выходит на плато; нет дыр, смены опоры, пропажи изменений, копий акторов и остановок на обычном пути.

**Критерии:** измерять время до управления машиной, p95/p99 и максимумы кадров на въезде, максимальный неделимый шаг, отставание готовых участков от машины, JS/GPU/общую память после 10–15 минут и повторного маршрута, первый запуск без кеша. Начальная продуктовая цель — вход в смену за 5–10 с на физической Деке при сохранении высокой графики; пока это цель для проверки, а не достигнутый или гарантированный срок. Если готовая земля сама по себе мало ускорит старт, следующий слой выбирается по замерам 17а. №9 (склейки) и №13 (дальность) не включаются автоматически в эту работу.

**Следующий реализуемый пакет ранних адресных данных · S, решение главного агента02.11.2026; в работе.** После четырёх принятых случаев — один настоящий ранний private provider и один упакованный файл для точного подтверждённого B1-входа: mature район0/high/ru/«Семёрка», actual initial season2.5, trash0. Не расширять сразу на newbie/mid, другие машины/районы или весь диапазон сезона/доната. B1/B2/S и исправленный T совпали; первая T-попытка сохранена как ошибка fixture: без `dlv-money-x8` обычная миграция умножила rawдонат480000 на8. Исправленная T raw60000 дала actual480000/fraction1. Ключ обязан использовать фактическое состояние **после** bootstrap и денежной миграции, не исходный JSON fixture (baseline wallet также стал240000).

1. **Малый формат/модуль.** Чистый `addressdata.js` (codec + закрытый provider/reconcile; при необходимости codec отдельным коротким файлом), без Three/RNG/часов/Store/сцены. Версионированный LE-файл: magic/version, bounded header/body length и CRC; SHA файла — снаружи в каталоге, не в собственном header. Identity `{mapId,mapHash,editsHash,sourceHash,inputHash}`. Блоки: Float64 house x/z/mx/mz/lv, UTF-8 addr/name через индексы; building ordinal + типизированный raw sourceId; Float64 generated-door x/z/nx/nz + grand flag + building ordinal; Float64 SPOTS x/z. Raw entrances сверяются с текущим исходным prefix, затем provider заимствует эти же строки; список entrances описывается prefix + ссылки на canonical generated-door rows, без дублирования дверей. Сохранять порядок/−0/типы ID/первый nearest-tie; ordinal разрешается только в настоящий post-prep CITY.buildings. Header/offsets/ranges/finite/UTF-8/links/counts/рабочий бюджет проверять до создания выходных объектов. Начальные явные ceilings: header64KiB, файл16MiB, расчётный working64MiB; это ограничения формата, не замер RAM. Размер реального адресного пакета ещё измерить.
2. **Ранний конечный ключ.** Считать непосредственно перед `buildCity`, когда уже выполнены денежная миграция, map/terrain fix, DIST.init и SEAS.initSeasons, но HOUSES/GEN_ENTR/SPOTS ещё не построены. Ключ — source/map/edits + exact post-prep numeric карта/terrain/исходные entrances + фиксированный canonical runtime/query descriptor + actual initial season/forced, donation fractions/raw/goal, DIST/opened/city, car-owned/current/upgrades/paint/engine, gfx device/preset/options, ru и ordinary EDL ownership/provider/baseSeed. Для первого S нужен явный opt-in `addresspackage17b` и один конечный разрешённый descriptor B1, а не default-reader для всех сохранений. Перечень gameplay-полей конечен: post-migration money-version/wallet, shifts/stars, season, trash/gang, district/opened/dist-shifts/city/party, guide/tutorial flags, car-owned/cur/up/L/paint/eng и story/USED/clock/weather-cycle presence. Точные значения/отсутствие извлекаются из actual B1 до визуала и проверяются дважды; другое значение или неизвестный gameplay-key — miss. Не хешировать весь Store: случайные owner/saveId, timestamps, migration journal/backup и telemetry исключаются явной служебной схемой, а не игнорированием всех неизвестных ключей. DIST/car/gfx/lang пока не обобщать: только exact B1, не all-values proof. Не подставлять поздние HOUSES/SPOTS/paths или их hash вместо входа. Минимальное недостающее доказательство — зафиксировать этот actual post-migration whitelist/ключ на двух B1-процессах; сейчас initial observer не включает wallet и все progress keys. Новичок/mid потребует собственной конечной записи и двух actual экспортов, а не `shifts===0`.
3. **Доставка до визуала без TLA в game.js.** Один ограниченный optional preload готового файла на существующем async-барьере main.js перед импортом game; early raw save может только выбрать кандидата, не подтвердить key. Итоговый exact key/derived inputs проверяются уже перед `buildCity`. Пакет bytes/manifest инициализирует отдельный data-only модуль, а не platform→game import cycle. Отсутствие/таймаут/неподдержанный descriptor/неверный SHA/формат/вход до публикации освобождает данные и оставляет один прежний generated путь. Для первого S — один B1 asset, без новой универсальной матрицы или собственного менеджера кеша; source key не включает generated package/buildversion, final package inventory/SHA проверяются отдельно.
4. **Атомарность и настоящий ранний потребитель.** Полностью decode/validate/resolve links в detached состоянии; затем одной операцией открыть private `queryAddress(x,z)` / `queryEntranceLevel(x,z,r)` и метку ready **до** вызова buildCity. Это отдельный явный API для будущего17в и диагностического consumer, не замена legacy helpers. Текущие `realAddress`/`nearEntrance`/`entranceLv`, глобальные HOUSES/GEN_ENTR/CITY.entrances/SPOTS и Go/LATE-barrier сохраняют прежнюю видимость/фазы. Некоторые callers работают во время сборки; переключить их на полный early-каталог без отдельной проверки нельзя. Корневой API можно freeze, live row-объекты и Store-ссылки не замораживать. Decoder возвращает immutable snapshot; replay заранее создаёт из него один detached набор canonical **mutable** live rows, не вставляет frozen snapshot-строки в прежний мир.
5. **Replay без двойных строк и без смены генерации.** Старые visual builders выполняются полностью, со всеми `entranceAt`, фасадным RNG/UUID и прежними yields. `emitAddressHouse/emitGeneratedDoor` сверяют ordinal/rawid/поля через Object.is с очередной записью файла и вставляют её canonical row в **существующий** live array на прежнем событии; временный candidate не накапливается второй копией. CITY.entrances до `mergeDoorsOnce` остаётся только raw-prefix: иначе `genEntrances` увидит собственную готовую дверь, пропустит геометрию/F0 и изменит RNG. Старый merge однократно добавляет те же door-refs; `osmDoorsNear` не получает будущие двери раньше срока. Для SPOTS — один optional acceptSpot callback в pure addresslayout в прежней точке принятия, возвращающий canonical row перед тем же push/grid insert; генератор/фильтры/порядок/yields не пропускать. Reconcile сравнивает со скалярами исходного packed блока, не объектом, уже разделяемым с live-миром. После seal проверить counts/order/links/aliases и отпустить проверочные buffers. Несовпадение после ранней публикации — fatal/остановка старта с диагностикой, не silent generated поверх уже опубликованных адресов.
6. **Конечная приёмка S.** Tiny codec/reconcile fixtures: −0/UTF-8/ID-type/ties, bounds/CRC/identity, несовпадение до publish → generated1, early provider не меняет raw-prefix/legacy partial queries, тот же row-ref при old emissions/merge/SPOTS, mismatch после publish → fatal. Затем одна immutable candidate с generated/package ветками: на точном B1 два actual процесса. В package процессе синхронный readonly диагностический consumer непосредственно перед вызовом `buildCity` вызывает private query API на заранее зафиксированных B1-точках, подтверждает старые live lengths/prefix и отсутствие visual emissions; сохраняет таблицу. Наблюдение через eval уже после синхронного buildCity за ранний вызов не выдавать. После полного reconcile — прежние actual realAddress/entranceLv/DOOR/Gennady/POOL/USED checks и точное сравнение с generated контролем, actual Go/W и сохранённые ключи. ASAR wire/header identity/inventory — отдельная проверка того же файла. Это доказывает ранние данные и consumer contract, не раннее управление или выигрыш секунд; граф остаётся дешёвым generated, снятие общего барьера и ускорение относятсяк17в/17г.
