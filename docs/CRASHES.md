# Журнал ошибок и зависаний

Зачем: на Steam Deck однажды мир встал — машина, люди и часы стояли, а пауза и большая карта
открывались; помог только перезапуск. Так бывает, когда в обновлении мира каждый кадр падает
одна и та же ошибка: пауза и карта рисуются раньше этого места, поэтому живы. Раньше такие
ошибки никуда не записывались. Теперь у игры есть журнал, сторож и предохранитель.

Код: `src/platform/crashlog.js` (журнал, сторож, предохранитель, окно в паузе), подключение —
`src/main.js` (как можно раньше) и цикл кадра в `src/game/game.js` (`frame` / `frameStep`),
запись в файл — `electron/main.cjs` + `electron/preload.cjs` (`birdSteam.log`).

## Что делает игра

| что | правило |
|---|---|
| **журнал** | ловит любую необработанную ошибку страницы, отказ промиса и ошибку из кадра. Хранит последние **50** записей. Одинаковые (вид + где + текст + верх стека) — одна запись со счётчиком «×N» |
| **снимок** | к каждой *новой* записи: версия сборки, площадка (steam/web), карта, район, пиццерия, состояние (`S.state`), пауза / карта / диалог, часы смены, время суток и сезон, дождь, заказ (вид, какой адрес из скольких, сколько метров), машина (x, z, высота, курс, км/ч), сердца, деньги, развезено, сколько машин и людей, заглохла ли, сюжетная сцена, fps, сколько кадров с запуска, в каком куске кадра упало, какие части мира выключены, последние **20** событий (смена состояния, тосты, ошибки) |
| **предохранитель** | каждая часть мира в кадре (трафик, прохожие, самокатчики, скорая, вор, аварии, пробки, конкуренты, веранды, курильщики, кальянщики, вечеринки, деньги на улице, багажник, линия маршрута, следы колёс, гайд, кровь и куски, мусор и контейнеры, удары по людям, эффекты, небо и время суток, сезоны, толпы, ночная жизнь, парочки, мир, мафиози, звери, коты, каток, бригады, сёрферы, футбол, радар) идёт под защитой. Упала — запись в журнал, кадр идёт дальше. Упала **3 кадра подряд** — выключается до конца сессии (игра едет без неё), внизу плашка «что-то споткнулось — отчёт сохранён» (не чаще раза в 20 с) |
| **ядро** | езда, камера, заказы, смена, районы, нитро, мотор, хад — без выключения: ошибка пишется в журнал, остаток кадра пропускается, картинка всё равно рисуется. Мир от этого может стоять — но запись есть, и сторож тоже сработает |
| **сторож** | идёт смена, не пауза, не карта, не диалог, не катсцена, не гараж, кадры зовутся, а мир **3 с** не продвинулся — запись «зависание» (со снимком и последней ошибкой). Пошёл снова — событие «мир снова идёт», следующее зависание запишется опять |
| **Электрон (Стим, Дека)** | страница перестала отвечать (бесконечный цикл) или упала — оболочка сама пишет это в тот же файл |

На обычном ходу (ошибок нет) журнал не тратит ни памяти, ни времени кадра.

## Где лежит файл

Электрон (Стим, Дека, сборки с GitHub) пишет **файл в день** — `crash-ГГГГ-ММ-ДД.log`, не больше 1 МБ,
хранятся 7 последних файлов:

| где играешь | папка |
|---|---|
| Steam Deck (и любой Linux) | `~/.config/BirdPizza/logs/` — на Деке это `/home/deck/.config/BirdPizza/logs/` (папка `.config` скрытая: в Dolphin — Ctrl+H) |
| Steam Deck, если вдруг через Proton (виндовая сборка) | `~/.local/share/Steam/steamapps/compatdata/<App ID>/pfx/drive_c/users/steamuser/AppData/Roaming/BirdPizza/logs/` |
| Windows | `%APPDATA%\BirdPizza\logs\` (обычно `C:\Users\<имя>\AppData\Roaming\BirdPizza\logs\`) |
| Mac | `~/Library/Application Support/BirdPizza/logs/` |
| браузер (web, Яндекс) | файла нет — последние 30 записей в `localStorage`, ключ `dlv-crashlog` |

Папка — та же `userData`, где сохранения (`electron/main.cjs` закрепляет имя `BirdPizza`, оно не
зависит от `productName`). Последние 30 записей и в Электроне дублируются в `localStorage`.

## Как автору отправить отчёт

1. Пауза (Esc / ☰). Если в журнале что-то есть — в правом нижнем углу, над версией, появится
   маленькая кнопка **«отчёт об ошибке»**. Нет кнопки — журнал пуст.
2. В окне — последние записи (когда, ошибка / зависание / выключено, где, ×сколько раз, текст).
3. **«скопировать»** — весь журнал в буфер обмена: первая строка — версия и площадка, дальше по
   записи в строке. Вставить в чат с Claude как есть.
4. В Стиме и на Деке есть ещё **«открыть папку с отчётами»** — откроется папка с файлами, путь
   написан в окне. Можно приложить файл или просто написать Claude путь (если он работает на этой
   же машине — прочитает сам).
5. **«очистить»** — стереть журнал (после того как отправил). Файлы на диске остаются.

На Деке в игровом режиме буфер обмена работает внутри Стима плохо — проще в режиме рабочего
стола: Dolphin → `~/.config/BirdPizza/logs/` → файл за нужный день.

## Как агенту прочитать

Файл — JSON-строки (JSON Lines). Одна запись = одна строка. Когда счётчик растёт, игра раз в
~5 с дописывает ту же запись ещё раз с тем же `id` и новым `n` — **по каждому `id` бери последнюю
строку**. Строки с `"where":"electron"` пишет сама оболочка (зависла / упала страница).

```
tail -n 200 ~/.config/BirdPizza/logs/crash-*.log | jq -c '{id, kind, where, n, msg, last, phase: .snap.phase, state: .snap.state}'
```

Поля записи:

| поле | что |
|---|---|
| `id`, `session` | номер записи и запуска игры |
| `kind` | `error` (необработанная ошибка), `rejection` (промис), `frame` (ядро кадра), `step` (часть мира упала), `fuse` (часть мира выключена после 3 падений подряд), `freeze` (сторож), `crash`/`info` (оболочка) |
| `where` | `window`, `promise`, `frame:<кусок>` (`pre`, `drive`, `orders`, `nitro`, `districts`, `career`, `car`, `hud`, `render`), `step:<часть>` / `fuse:<часть>` (имена — первые аргументы `CL.step('…')` в `frameStep` в game.js: `traffic`, `hits`, `junk`, `mafia`, `cats`, `nightlife`…), `watchdog`, `electron` |
| `msg`, `stack` | текст ошибки и стек (до 1 500 символов). Сборка минифицирована: имена функций в стеке короткие, место — `index-<хеш>.js:1:<колонка>` |
| `n`, `first`, `last` | сколько раз, первый и последний раз (UTC) |
| `snap` | снимок (см. выше): `build`, `platform`, `map`, `district`, `state`, `shiftT`, `clock`, `order`, `car`, `fps`, `phase`, `off` (выключенные части), `events` |
| `lastError` | у `freeze` — последняя ошибка перед зависанием |

Найти место по стеку из релиза: собрать ту же версию с картой исходников —
`git checkout v0.0.N && npx vite build --mode steam --outDir /tmp/bp-map --sourcemap` — и найти
колонку из стека в `.map` (например `npx source-map-cli resolve`), или просто начать с `where` /
`phase` — они уже говорят, какая часть кадра упала.

В игре без файла: `__dlv.crashlog` (с `?debug`) — `entries()`, `count()`, `text()` (то же, что
копирует кнопка), `disabled()` (выключенные части), `clear()`.

```
npm run probe -- --js="d.HITS.STATS.WRECKS.push({ o: null, life: 99 }); await run(1); return d.crashlog.entries().map(e => [e.kind, e.where, e.n])"
```

`smoke()` в probe возвращает `crash` (записи журнала) и проваливается, если журнал не пуст;
`npm run check` печатает записи под проваленным дымовым прогоном и отдельной строкой
«журнал ошибок пуст после дымовых».
