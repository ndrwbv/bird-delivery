# Как агентам быстрее и дешевле работать с игрой

Разбор по итогам 02.10.2026: блоки 1—5 плана (теперь — IDEAS-ARCHIVE.md) делали 16 субагентов, по 3—5 параллельно, каждый
тратил 180—350 тыс. токенов. Ниже — что реально съедало время и токены и что с этим сделать. Всё,
что не помогает напрямую, сюда не попало.

## Где уходило время

| проблема | как проявлялось | цена |
|---|---|---|
| dev-сервер перезагружается от чужих правок | почти каждый агент останавливал свой `vite` и собирал свою копию + `vite preview` | лишние сборки, путаница с портами |
| панель браузера скрыта | `requestAnimationFrame` стоит, игра не идёт; агенты двигали время и кадры руками из консоли | десятки лишних вызовов |
| проверка скриншотами | 1—1,5 тыс. токенов за кадр, часто ради чисел, которые можно прочитать из `__dlv` | основная статья расхода на проверке |
| чужая вкладка | дважды скрипт из консоли выполнился во вкладке другого агента и поменял его сохранение | сломанные проверки |
| переводы в каждом агенте | каждый переводил свои строки на 13 языков и боялся перезаписать `_source.json` | ~10—20 % токенов агента |
| длинный `game.js` (13 тыс. строк) | агенты по многу раз грепали и читали куски, чтобы найти нужное место | ориентирование в начале каждой задачи |
| длинные промпты | правила (не трогать git, свой порт, детская/взрослая версия, доки) повторялись в каждом задании | мелочь, но в каждом агенте |

## Что сделать — по пользе

### 1. `npm run probe` — «одна команда — ответ» (сделано)

Собранная игра в Электроне вне экрана: окна нет, панель браузера не нужна, кадры идут сами.
Открывает игру с `?debug&mute&nolb&nointro`, ждёт `window.__dlv`, выполняет скрипт, печатает JSON.

```
npm run probe -- --js="return d.S.state"                       # ~4 с
npm run probe -- --js="await onShift(); autopilot(); await run(10); return d.S.delivered" --shot=out.png --scale=0.5
npm run probe -- --eval=my-check.js --size=phone --errors
```

- скрипт (`--js` или `--eval=файл`) — тело async-функции в странице. Есть: `d` (= `__dlv`),
  `wait(ms)`, `until(fn, ms)`, `run(secs, k)` — дать игре идти (k — ускорение до 3),
  `onShift()` — начать смену и принять заказ, `ride()` — просто кататься, `tp(x, z)` — машину
  на ближайшую дорогу, `autopilot(on)` — едет по маршруту и принимает следующие заказы,
  `frames()` — время кадров, `smoke(secs)` — смена на автопилоте и проверка «игра жива»,
  `log(x)` — строка в вывод. `return` — JSON в stdout (обрезается до 4000 символов, `--max=0`);
- `--mode=web|yandex|steam`, `--kids`, `--map=`, `--lang=`, `--q=a=1&b` (добавка к адресу),
  `--size=desktop|phone|phone-land|phone-se|phone-big|deck|WxH` (телефон 390×844 с касаниями — стоя, с `?portrait`;
  игра на телефоне только боком: `phone-land` 844×390, `phone-se` 667×375, `phone-big` 932×430; `--turn` — стоя как
  настоящий, с заставкой «поверни телефон»; `--sa=59,21` — вырез и полоска «домой»; повернуть из скрипта —
  `console.log('__proberesize:844x390')`), `--secs=N` (идти после
  скрипта), `--shot=out.png --scale=0.5`, `--errors` (текст ошибок консоли; счётчик — всегда),
  `--fresh` (первый запуск как у новичка: подсказки первой смены, учебный заказ; вступление-катсцена — ещё `--q=intro`);
  `--cpu=3` — процессор втрое медленнее (как у Steam Deck), после загрузки;
- кадр посреди скрипта — `console.log('__probeshot:/путь/a.png'); await wait(600)` (несколько экранов за один запуск);
  геймпад без геймпада — подменить `navigator.getGamepads = () => [gp]` (стандартная раскладка: A 0, B 1, X 2, Y 3,
  крестовина 12—15) и жать `gp.buttons[i].pressed` на ~120 мс; курсор — элемент с классом `.padsel`;
- `--page=ui.html` — другая страница сборки: песочница интерфейса (`--q=frame` — сам экран,
  `window.__ui`; без — панель, `window.__uilab`), [SANDBOX.md](SANDBOX.md) → «Песочница интерфейса»;
- сборка — в `os.tmpdir()/bird-probe/<mode>.*`, только если `src/`, `public/`, `index.html`,
  `sandbox.html`, `pad.html`, `ui.html` или `vite.config.js` новее (+3—5 с); `--rebuild` — всегда,
  `--no-build` — не собирать. `dist/` не трогает; `--dir=папка` — готовая сборка вместо своей
  (релиз: `BUILD_VERSION=0.0.99 npx vite build --mode steam --outDir папка` — в ней прячется то, что
  только для тестов; вернуть — `?debug`, который probe и так добавляет);
- каждый запуск — с чистым сохранением (сессия в памяти, своя userData): агенты не мешают
  друг другу и не трогают сохранение автора;
- код выхода 1 — необработанная ошибка в странице, исключение в скрипте или игра не загрузилась.

Полный список флагов — в шапке `tools/probe.cjs`. Скриншот — только для внешнего вида, числа
читать из `__dlv`.

**Анонимная статистика в проверках не уходит** (`?debug` / `?mute` — копится в `__dlv.tel`, но не шлётся;
[ANALYTICS.md](ANALYTICS.md)). Проверить приёмник нарочно — `--q=tel` (события с пометкой `test`), потом
`npm run stats -- --test --print`.

**Автопилот** (`tools/probe-page.cjs`, 03.10.2026) ездит как осторожный игрок: не быстрее 14 м/с
(у стен — 10, удар о стену бьёт сердца только быстрее 15 м/с), тормозит перед машинами и теми, кто
вот-вот въедет сбоку, объезжает стоящих по встречке, если она свободна; ремонт поперёк улицы
(навигатор нарочно ведёт прямо в него) объезжает своим путём по улицам; к пину во дворе, до которого
от улицы 100 м за заборами, ищет проезд по клеткам; со двора выезжает тем же путём; от тарана
конкурента уходит газом. **Сколько ждать:** первая смена у новичка короткая — ~240 с игры, то есть
`run(80, 3)`. `d.S.state === 'over'` после `run(90, 3)` — обычно просто конец смены; причина гибели —
`d.DEATH.why` («машина всё», «утонул»; пусто — смена кончилась сама). Ориентир: 2—3 доставки за
`run(90, 3)` (9 прогонов: 2—3, в среднем 2,4; до 03.10 — 0—4, в среднем 1,2, два раза машина всё).
**Окна, что ждут игрока** (10.10.2026; окно разговора с 16.10.2026 мир не стоит — машина стоит сама): автопилот через ~0,8 с жмёт кнопку, как игрок мышью: диалог
(приглашение клиентки, Толик, поручения, гопники) — «отказаться» (гопникам — заплатить; одна кнопка — она), карточка
(обед, «воскреснуть?») — первый вариант, просьба клиента — отказ; пауза без окна — снимает. Что и сколько раз закрыл —
`P.ap.closed`, самая долгая стойка мира, с — `P.ap.maxStall`; `apStats()` и поле `ap` в ответе `smoke()`.

### 2. `npm run check` — общие проверки перед сдачей (сделано)

~45 с (со сборками ~55 с). Агент запускает перед отчётом, я — перед коммитом. Таблица, код выхода 1
при провале:

| проверка | что |
|---|---|
| сборки web / steam (Яндекс — только по просьбе автора) | `vite build` во временные папки (свежие не пересобирает; `--rebuild` — заново) |
| `i18n:check` | ошибки — провал, непереведённое — только предупреждение |
| заказы в открытых районах, город поделён | открыто 1…8 районов × работаешь в новейшем и в первом × номер заказа 0 / 12 / 40 / 90: ~10 000 адресов `ORD.simShift`, у каждого район и район ближайшей дороги открыты и он в районе, где работаешь; и весь город поделён — каждый адрес, подъезд и дом (`SOLIDS`) в каком-то районе, ничьих 0 (`tools/probe-checks/orders-open.js`) |
| сугробы снежной зимы | у ~12 000 сугробов погоды «снежная зима» край не на асфальте, ни адрес заказа, ни дверь подъезда не в сугробе и не ближе 1,5 м; вариант включается, в грозу идёт дождь (`tools/probe-checks/weather-drifts.js`) |
| постройки не на дороге | свои дома-контуры (пустыри, точки конкурентов, стройки, пиццерии-шары, клуб), участки строек, пустырей, костров и котлов, песок пляжа, гаражи-ракушки газона — ни одной точки на асфальте (до края каждой дороги, кроме пешеходок) (`tools/probe-checks/buildings-road.js`) |
| заборчики и конструкции не на тротуарах | «где ходят» — `pave.js` (полотно, тротуар 2,75 м, пешеходки, дорожки, аллеи): середина ни одного сбиваемого забора города (кроме веранд конкурентов), ни одна опора оградок, выбивалок, бельевых столбов, ракушек, песка, покрышек и ни один стебель зарослей у каждого 15-го подъезда — не на мощёном (`tools/probe-checks/pave-props.js`) |
| дорожки дворов в сети, точки конкурентов за тротуаром | у каждой тропинки от двери конец — на общей дорожке или у проезда; у каждой общей дорожки есть выход на тротуар, пешеходку, край проезда, аллею или чужую дорожку, не сквозь дом и забор, без хвостов в газон; участок каждой точки конкурента не на тротуаре, дорожке и аллее, от тротуара к ней — своя дорожка (`tools/probe-checks/yard-paths.js`) |
| машины не призраки и твёрдые, лось не сквозь | 45 с смены на автопилоте (×3): у каждого видимого кузова машины ближе 220 м есть живая машина потока на том же месте, у каждой машины склейки стоящих — живая нетронутая там же, у каждой живой ближе 220 м — кузов (`parkmerge.js`); кто стоит дольше 30 с — с причиной (без — предупреждение); курьер на 9 м/с не проходит сквозь стоящую припаркованную, машину потока и автобус; лось не проходит сквозь припаркованную и автобус, с разбега отбрасывает машину (`tools/probe-checks/ghost-cars.js`, ~50 с) |
| маршрут навигатора не сквозь дома | ~300 случайных адресов: от пиццерии, с улицы в 250—900 м и выезд со двора к другому адресу — ломаная `roadPath` через 1 м не заходит в контур дома (арка — не дом); старт или адрес дальше 230 м от улицы (за окном поиска по клеткам, напр. точка в 300 м от дорог в промке на севере) — не провал, считается в `far` (адрес — с 10.10.2026); печатает и «по-старому» (`RYARD.RY.OFF`) и время поиска по клеткам (`tools/probe-checks/route-house.js`) |
| дворы сложнее: клиенты достижимы | ~700 адресов по всему городу: от адреса по клеткам навигатора (заборы у тротуаров, клумбы, изгороди, лесочки — стены) доехать до улицы, заперто ≤ 0,5 %; маршрут от пиццерии не пересекает твёрдое лабиринта (`tools/probe-checks/yard-maze.js`, `--q=nomaze` — сравнить без него; CAREER.md «Дворы сложнее») |
| 30 с автопилота: взрослая (web), телефон боком (web, `phone-land`) | без необработанных ошибок; машина проехала ≥ 150 м, кадры и часы смены идут, координаты, деньги и сердца — числа, в конце — смена, не меню и не диалог; время кадра p50 / p95 (p95 > 33 мс — предупреждение) |
| память на телефоне | мобильный режим боком `--size=phone-land` (до 11.10.2026 — стоя `phone`), меню → достроен → 20 с смены (`tools/probe-checks/memory.js`): куча JS в меню ≤ 520 МБ, в смене ≤ 620, видео ≤ 360, пик следа страницы ≤ 1450 (macOS) — см. «Память на телефоне» |
| одно уведомление за раз | 60 с средней смены на автопилоте, через 6 с езды машину переносит к адресу (вручений втрое больше); раз в 50 мс по самому экрану — сколько всплывающего видно сразу (чек оплаты, реплика на ходу, новое сообщение чата, тост, грамота, задание, записка, подсказка, таблица рейтинга): два и больше сразу — провал (`tools/probe-checks/notify-one.js`, `--q=nsecs=200&nshift=0&ntp=8` — свои условия; CAREER.md «Одно уведомление за раз») |
| журнал ошибок пуст после дымовых | предохранитель в кадре глотает исключения (в консоли они уже не «Uncaught») — `smoke()` возвращает записи журнала `d.crashlog` ([CRASHES.md](CRASHES.md)), провал печатает их |

`--only=orders,smoke` — только эти, `--serial` — дымовые по очереди (по умолчанию разом).
Новый инвариант — элемент массива `CHECKS` в `tools/check.cjs`; скрипт в игре — файлом в
`tools/probe-checks/`.

### 3. Короткий `CLAUDE.md` в корне репо

Его автоматически читает каждый агент, поэтому правила не надо повторять в задании. 30—40 строк:

- две версии: детская (Яндекс) и взрослая (Стим);
- как проверять: сначала `probe` и числа из `__dlv`, скриншот — только для внешнего вида;
- строки: только ru + en (см. п. 4).

### 4. Переводы — один проход на блок

Агенты пишут строки только по-русски и по-английски. В конце блока один агент добавляет
остальные 12 языков и запускает `i18n:extract`. Так уже сделали после блока 1 — и это было
дешевле, чем переводы в каждом агенте.

### 5. Свой порт и вкладка на агента

Если без браузера никак, у агента свой слот (`.claude/launch.json`: `agent-1`…`agent-8`, порты
5201—5208) и скрипты только в своей вкладке.
dev-сервер для агентов — без перезагрузки от чужих правок (флаг в `vite.config.js`:
`server.watch: null`, `hmr: false` по переменной окружения). С `probe` это нужно редко.

### 6. Карта `game.js` — по желанию

`npm run codemap` печатает разделы `game.js` (по комментариям-заголовкам) с номерами строк — 20
строк кода, генерируется на лету, поэтому не устаревает. Делать, только если п. 3 (новые системы —
в свои файлы) окажется недостаточно.

## Запуск до меню: что строится сразу, что потом (09.10.2026)

Город строился весь при загрузке, до первого кадра меню: ~5 с на обычном компьютере, ~14,5 с на
«Деке» (`--cpu=3 --bootcpu`; автор на настоящей Деке — 12,5 с). Теперь (`src/game/latebuild.js`, порядок — `buildCity` в game.js):

| когда | что |
|---|---|
| **сразу**, до меню | земля, дороги, бордюры, разметка, мосты, край карты, рельсы, ремонт дорог, дома (фасады, окна, муралы), пиццерии; меню, профиль, хад |
| **потом**, очередью после 3-го кадра меню, кусок за куском, в том же порядке, что раньше | всё из `buildCity` после домов: ночная жизнь, аллеи и особняки, стройки, точки конкурентов, тёмная ночь, пустыри, жизнь улиц, подъезды и дорожки дворов, продухи, вывески, ворота, деревья, метро, парковки, фонари, пандусы, заправки, знаки и заборы, щиты, ямы и гараж, дворы (5 кусков), сугробы и листва, тропинки; потом склейка этого в те же клетки статики, загрузка в видеокарту, реквизит, ельник, лес у Ленина, мелочь на газоне, припаркованные и поток, адреса заказов, погода, нитро, районы графа (lock — 0), кальянщики, прохожие, ночь, шейдеры, заморозка (`CULL.freeze`) |

- Пока очередь не пуста, мир за меню **стоит** (машины, люди, часы суток), камера не облетает, город
  перерисовывается раз в 0,2 с — кадры не отнимают время у стройки.
- **Город за меню, пока строится, — не в фокусе** (размыт на 5 px, чуть светлее; `body.late-haze`,
  delivery.css): деревья, фонари, лавочки появляются за дымкой, а не разом на глазах. Достроился —
  резкость наводится за 1,4 с; ушёл из меню раньше (смена, гараж, экран загрузки) — сразу.
- **Долгие куски идут шагами** (10.10.2026): кусок может вернуть итератор (`function*` и `yield`),
  latebuild.js делает шаг, отдаёт кадр, снова шаг. Шаги стоят по счёту (каждые N домов, улиц, участков),
  не по времени — поэтому город при `?nolate` и без одинаковый, `--seed` перед каждым шагом свой
  (`имя#номер`). Шагами: подъезды и дворы (game.js `osmEntrances`/`houseWalks`, yards.js `steps`),
  сугробы и гирлянды (seasons.js `seasonSteps`, склейки `Pile.steps`), деревья дворов (trees.js
  `plantYardsSteps`), знаки и заборы (roadlife.js `build`), точки конкурентов (rivals.js), пустыри
  (wastelands.js), стройки (construction.js; поиск участков — `freeLotsSteps`), аллеи и особняки
  (world.js), жизнь улиц (`osmStreetLife`), мелочь дворов, склейка реквизита (`mergeChunked`).
  `__dlv.LATE.MAX` — самый долгий шаг куска, `LATE.STEPS` — мс по шагам (`yield 'имя'` — подпись).
  Горки и снеговики (seasons.js `seasonYard`) — не шагами, а быстрее: «рядом ли мелочь» по клеткам 8 м
  вместо перебора 25 тыс. на каждую пробу.

| «Дека» (`--cpu=3 --bootcpu`), меню стоит дольше всего | до | после |
|---|---|---|
| подъезды и дворы (`entr`) | 1,3—1,5 с одним куском | шаг ≤ 50—60 мс (весь кусок те же ~1,4 с) |
| сугробы (`seasons`) | 0,65—0,85 с | шаг ≤ 100—120 мс (сборка шейдеров зимы — одним шагом) |

## Мелкие разгрузки (10.10.2026)

Четыре мелочи, которые шли каждый кадр:

## Шейдеры на ходу (10.10.2026)

Программа шейдера (материал × вид объекта × свет и туман) собирается при первой отрисовке. Посреди смены это рывок:
сама сборка и ожидание видеокарты (`getProgramInfoLog` при первом использовании) — на «Деке» 2—30 мс на программу,
на настоящей Деке, скорее всего, больше. Счётчик — `renderer.info.programs.length` (сколько живо), текстур —
`renderer.info.memory.textures`.

**Как мерить:** `npm run probe -- --eval=tools/probe-checks/shaders.js --cpu=3 --size=deck --max=0 --timeout=600`
(имена в «откуда» — со сборкой без сжатия: `npx vite build --mode web --minify false --outDir папка`, потом `--dir=папка`;
`--q=shsecs=5` — секунд на этап, `--q=shonly=ночь,гроза` — только эти этапы, `--q=weather=snowy` — заход зимой).
Смена на автопилоте, этапы по очереди: старт смены, ночь, утро, дождь, гроза (молнии), жара, золотой час, снег, снег ночью,
ураган, нитро, бист, взрыв, машина горит, кровь, удар, авария, погоня, вор, три фестиваля, протест, мафия, налёт,
пиццерия-шар вблизи днём и ночью, катсцена, повтор, три конца города. Ответ: `links` — какие программы собрались посреди смены
(кто рисовался, материал, где создан), `waits` — где ждали видеокарту дольше 1 мс (`linked` — собрана при загрузке или на
ходу), `long` — кадры > 50 мс и кадры со сборкой, `phases` — по этапам (новые программы и текстуры, JS кадра, ожидание, загрузки
текстур), `mats` — материалы, созданные в смене (по месту), `tex` / `canvas` / `ups` — текстуры, холсты и загрузки в видеокарту,
`ls` / `store` — записи сохранения. Всё ловится обёртками в странице: `gl.linkProgram`, `getProgram*`, `texImage2D`,
`renderer.renderBufferDirect` (кто рисуется), `uuid` у Material/Texture (где создан), `Storage.setItem`, `createElement('canvas')`.

## Граффити и портреты (10.10.2026)

**Откуда рывки.** Оба рисуют на холсте `<canvas>` и читают его обратно (`getImageData`, `toDataURL`). Обычный холст

## Частицы и мусор в памяти (11.10.2026)

**Частицы из запаса** (`src/game/fxpool.js`, `fxPart(вид, x, y, z, цвет, размер, прозрачность, движение, пол)`). Раньше каждая
искра, клуб дыма, язык пламени нитро, капля крови, обломок взрыва — свой меш со своим материалом (`fxAdd`): у кальянной компании
~100 новых материалов в секунду, нитро — ~38, на каждый three.js ищет программу и копирует униформы, каждая частица — отдельный
вызов отрисовки, потом всё это — мусор. Теперь вид — один `InstancedMesh` с общим материалом на всё время игры: `spark` (искры,
крошки), `bit` (кровь), `debris` (обломки, со светом), `puff` (дым из-под капота, пламя нитро, огонь, брызги, пар, кальян,
курильщики, электронка, ведьмин дым), `ring` (кольца кальянщика), `bubble` (пузыри детской). Цвет — у каждой частицы, прозрачность
прозрачных — своя (атрибут `aA`): в первом кадре — как была у материала, дальше «осталось жизни × 0,85», как раньше; движение, рост,
вращение, отскок, «эффекты: меньше» (через одну, короче) — те же. Прозрачные рисуются от дальних к ближним (сортировка вставками),
`renderOrder` 0,5 — после следов крови и копоти, до стёкол и воды. Виды на сцене с загрузки — программы собираются куском `shaders`
(`shaders.js`: `links` пусто). Запас растёт вдвое, если не хватило (`puff` — 512 с загрузки, до 8192). `fxAdd` остался для редкого
своего меша (значки эмоций, куски маскотов). **Новая частица — через `fxPart`, не `new Mesh` + `fxAdd`.** `?oldfx` — по-старому
(меш и материал на частицу) одной сборкой, для сравнения; `__dlv.FXP.S` — родилось, живо, пик, рост, `old`.

**Мусор в кадре** (`--allocprofile`, профиль по функциям; встроенное V8 приписывает вызвавшей):

Кости — это и есть `u.legL`, `u.legR`, `u.armL`, `u.armR`, `u.head`, `u.parts[2]` (туловище): `THREE.Bone` в тех же

- `u.parts` — `[legL, legR, туловище, armL, armR, head, skin]`: humanLod прячет их разом; `Box3.expandByObject(m, true)`

  не красят — только `set` / `setHex` / `setRGB` / `setStyle` / `copy`;
- `Box3.setFromObject(u.head)` (encounters.js — рост героя) — по 8 углам головы с волосами и убором (`u.head.geometry`,
  не рисуется);
- матрица кости = её матрица в группе × сдвиг от шарнира (скелет `HSkel`, `bindMode` detached, без мировых координат —

**Предметы в руках — в меш тела** (11.10.2026, people.js `holdFixed`). Было: что вешали на кость своим мешем
(`u.armR.add(...)`), — +1 вызов каждый (бутылка у толпы бара, лопата дорожника, лампасы и бита гопников — 4—5 мешей). Теперь

## Память на телефоне (11.10.2026)

Автор: «открываю с iPhone 17 в браузере — игра умирает на этапе меню». Safari убивает вкладку, когда её «след» (память
страницы: куча JS, массивы вершин, холсты) выходит за предел устройства. В Safari (симулятор iPhone 14, iOS 16.1 — тот же WebKit)
до правок след страницы доходил до **1,72—1,74 ГБ** на поздней сборке за меню и держался 1,15—1,22 ГБ — вот и смерть «в меню».

**Как мерить** (`probe --mem`):
- `npm run probe -- --eval=tools/probe-checks/memory.js --mem --early --size=phone --max=0 --timeout=400` — меню → город
  достроен → 60 с смены (`--q=msecs=20`): `heap` — куча JS после сборки мусора, МБ; `gl` — видеопамять по обёрткам WebGL
  (`tools/probe-glmem.cjs`: буферы, текстуры, кадр; `top` — самые большие текстуры с размером), `glJs` — сколько залитого ещё лежит
  копией в JS, `proc` — процессы Электрона: `page`, `gpu`, **`foot` / `footPeak` — след страницы (phys_footprint) и его пик** (macOS,
  утилита `footprint`; та же мера, по которой iOS убивает), `lateTopGl` / `lateTopHeap` — куски поздней сборки, что прибавили больше всех;
- в своём скрипте: `await mem('метка')`, `memLate()` (по кускам поздней сборки, нужен `--early`), `heapSnap('метка')` +
  `--heapsnap=папка` — снимок кучи; `--q=latesnap=kites,props` — снимок сразу после этих кусков (поздняя сборка стоит, пока снимают);
  `--q=lategc` — сборка мусора после каждого куска (осторожно: куча JS у V8 показывает и ещё не убранные буферы — точнее снимок);
- разбор снимка: `node tools/heapsum.cjs a.heapsnapshot [b.heapsnapshot] --who="system / JSArrayBufferData" --links=8` — кто держит
  массивы (имена — со сборкой без сжатия `npx vite build --mode web --minify false --outDir папка` и `--dir=папка`), два файла — разница;
- **настоящий Safari**: симулятор iPhone (`xcrun simctl boot …`), сборка `npx vite build --mode web --outDir папка`, раздать
  `python3 -m http.server 5299 --bind 127.0.0.1 --directory папка`, `xcrun simctl openurl booted "http://127.0.0.1:5299/?mute&nointro&lang=ru&debug"`
  и `footprint -p <pid com.apple.WebKit.WebContent> --noCategories` раз в 3 с (процессы симулятора — обычные процессы Мака).
- в `npm run check` — пункт «память на телефоне»: мобильный режим, `--size=phone-land`, 20 с смены; провал, если куча в меню > 520 МБ,
  в смене > 620, видео > 360 или пик следа страницы > 1450 (до правок было 706 / 822 / 289 / 1477).

на весь холст одним треугольником своей маленькой программой (собрана при загрузке: проверка сборки — ожидание видеокарты,

PROPS `light`) и стволы (SOLIDS `tree`) — полоски в той же маске: вершина `(x, высота, z)` + атрибут `aS` (полуширина поперёк
направления тени, у домов 0); маска 2048² (0,29 м на точку), иначе полоски рвутся. Сбиваемые — своей геометрией с копией в JS:
`down` проверяется по 160 в кадр, упал — полоска в точку (`addUpdateRange`), маска заново. Пятна машин — свой `InstancedMesh`
с картинкой как у carshadow.js, по кватерниону кузова; старые круги (`CircleGeometry` полной модели и машин курьеров, и у своей
машины) прячутся (`noCircle`). **Найдено:** cull.js (`freeze`) забирает в «статику» любой меш прямо на сцене с нулевым
положением и отсекает его по клетке, где был его шар при сборке. Под это попадали пятно своей машины (carshadow.js — пропадало
вдали от пиццерии, оставался круг: «странное пятно») и пятна теней — теперь они в своей группе (`Group`), её cull.js не трогает.
Тот же капкан — у любого меша, которому матрицу задают руками.

**Зерно города.** three.js даёт каждому новому материалу, геометрии и текстуре `uuid` из `Math.random`, а город строится с
зерном (editlayer.js подменяет `Math.random` на время сборки): объекты, созданные посреди сборки (на уровне модуля game.js
или в куске из списка `SEEDED`), сдвигают все случайные числа после себя — город выходит другим (первая версия теней так
поменяла адреса, и `npm run check` «маршрут сквозь дома» нашёл другой дом). Поэтому fakeshadows.js создаёт свои объекты со
своим генератором (`quiet`). Проверка: `route-house.js` с `?nofs` и без — одинаковые числа.
