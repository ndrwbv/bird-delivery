# Как агентам быстрее и дешевле работать с игрой

Разбор по итогам 02.10.2026: блоки 1—5 IDEAS.md делали 16 субагентов, по 3—5 параллельно, каждый
тратил 180—350 тыс. токенов. Ниже — что реально съедало время и токены и что с этим сделать. Всё,
что не помогает напрямую, сюда не попало.

## Где уходило время

| проблема | как проявлялось | цена |
|---|---|---|
| dev-сервер перезагружается от чужих правок | почти каждый агент останавливал свой `vite` и собирал свою копию + `vite preview` | лишние сборки, путаница с портами |
| панель браузера скрыта | `requestAnimationFrame` стоит, игра не идёт; агенты двигали время и кадры руками из консоли | десятки лишних вызовов |
| проверка скриншотами | 1—1,5 тыс. токенов за кадр, часто ради чисел, которые можно прочитать из `__dlv` | основная статья расхода на проверке |
| чужая вкладка | дважды скрипт из консоли выполнился во вкладке другого агента и поменял его сохранение | сломанные проверки |
| переводы в каждом агенте | каждый переводил свои строки на 13 языков и боялся перезаписать `_source.json` | ~10—20 % токенов агента |
| длинный `game.js` (13 тыс. строк) | агенты по многу раз грепали и читали куски, чтобы найти нужное место | ориентирование в начале каждой задачи |
| длинные промпты | правила (не трогать git, свой порт, детская/взрослая версия, доки) повторялись в каждом задании | мелочь, но в каждом агенте |

## Что сделать — по пользе

### 1. `npm run probe` — «одна команда — ответ» (главное)

Электрон вне экрана, как уже сделано в `tools/perf.cjs`, `tour.cjs` и `capture.cjs`, но для
любой проверки:

```
npm run probe -- --eval=check.js [--kids] [--size=phone|deck] [--secs=10] [--shot=out.png]
```

- открывает собранную игру с `?debug`, ждёт `window.__dlv`, выполняет скрипт агента, печатает
  JSON и выходит;
- кадры идут сами (нет троттлинга скрытой вкладки), время можно перемотать (`--secs`);
- каждый запуск — с чистым сохранением в своей папке: агенты не мешают друг другу и не трогают
  сохранение автора;
- скриншот только по флагу, уменьшенный — для того, что правда надо увидеть глазами;
- сборка — в свою временную папку и только если исходники новее.

Заменяет dev-сервер, вкладки и ручные кадры для ~80 % проверок. Ожидаемая экономия на проверке —
в 2—3 раза.

### 2. `npm run check` — общие проверки перед сдачей

Один прогон через `probe`, 1—2 минуты:
- сборки web / yandex / steam;
- `i18n:check` — без ошибок (непереведённое — только предупреждение, см. п. 4);
- заказы только в открытых районах: прогон смен без езды на 1—8 открытых районах (как проверяли
  02.10, 0 из ~9 000 адресов);
- 30 с автопилота по городу во взрослой, детской и телефонной версии — без ошибок в консоли,
  время кадра не хуже порога.

Агент запускает перед тем, как отчитаться, я — перед коммитом. Новые инварианты дописываются
по мере появления багов.

### 3. Короткий `CLAUDE.md` в корне репо

Его автоматически читает каждый агент, поэтому правила не надо повторять в задании. 30—40 строк:
- где правила мира (CAREER.md, ORDERS.md, IDEAS.md) и что доки обновляются вместе с кодом;
- git не трогать — коммитит главный (и только от личного аккаунта);
- новая система — в свой файл (`hits.js`, `junk.js`, `fauna.js`, `mafia.js`, `chat.js` — так уже
  делали), в `game.js` — только подключение;
- две версии: детская (Яндекс) и взрослая (Стим);
- как проверять: сначала `probe` и числа из `__dlv`, скриншот — только для внешнего вида;
- строки: только ru + en (см. п. 4).

### 4. Переводы — один проход на блок

Агенты пишут строки только по-русски и по-английски. В конце блока один агент добавляет
остальные 12 языков и запускает `i18n:extract`. Так уже сделали после блока 1 — и это было
дешевле, чем переводы в каждом агенте.

### 5. Свой порт и вкладка на агента

Если без браузера никак, у агента свой порт (`.claude/launch.json`: agent-orders 5201, agent-hits
5202, agent-coffee 5203, agent-map 5204, agent-hud 5205) и скрипты только в своей вкладке.
dev-сервер для агентов — без перезагрузки от чужих правок (флаг в `vite.config.js`:
`server.watch: null`, `hmr: false` по переменной окружения). С `probe` это нужно редко.

### 6. Карта `game.js` — по желанию

`npm run codemap` печатает разделы `game.js` (по комментариям-заголовкам) с номерами строк — 20
строк кода, генерируется на лету, поэтому не устаревает. Делать, только если п. 3 (новые системы —
в свои файлы) окажется недостаточно.

## Что не делаем

- юнит-тесты на Jest/Vitest: логика сплетена с three.js и DOM, тесты дорого писать и
  поддерживать, а `probe` проверяет то же самое на живой игре;
- сравнение скриншотов пиксель в пиксель: город живой (погода, прохожие), сравнение будет шуметь;
- CI на каждый пуш: релиз и так собирается в Actions, а `check` локально быстрее.

## Порядок

П. 3 и 4 — правила, делаются за минуты. П. 1 и 2 — один агент, примерно один вечер, окупается уже
на следующем блоке. П. 5 — одна строка в конфиге. П. 6 — только если понадобится.
