# Steam и Steam Deck

**Как залить в Steam по шагам — [STEAM-UPLOAD.md](STEAM-UPLOAD.md).**

Steam-бандл — это `vite build --mode steam` (→ `dist/steam`) внутри Electron-оболочки
`electron/`. Платформенный слой — `src/platform/steam.js`, мост в Electron — `window.birdSteam`
из `electron/preload.cjs`. Рекламы нет, таблица рекордов — таблица Стима «лучшая смена» (без Стима —
локальная, §4.2), есть «выйти из игры».

## 1. Сборка

| команда | что получается |
| --- | --- |
| `npm run electron` | собрать `dist/steam` и открыть в Электроне (`-- --windowed --log`) |
| `npm run dist:deck` | `release/linux-unpacked/` + `release/bird-pizza-deck.tar.gz` |
| `npm run dist:win` | `release/BirdPizza-*.zip` (собирать на Windows, см. ниже) |
| `npm run dist:mac` | `release/mac*/BirdPizza.app` — только для проверки |

Флаги запуска: `--windowed`, `--log`, `--page=pad.html` (диагностика геймпада), `--steam`,
`--no-update`, `--steam-overlay`. `F11` / `Alt+Enter` — полный экран.

**CI:** [.github/workflows/release.yml](../.github/workflows/release.yml), ручной запуск
(Actions → «Релиз» → Run workflow). Номер версии руками не вводится: выбираешь только, что
поднять — `patch` (правки: v0.0.7 → v0.0.8, по умолчанию), `minor` (заметное новое: → v0.1.0)
или `major` (→ v1.0.0); CI берёт последний тег `vX.Y.Z` и считает следующий (тегов нет —
v0.0.1 / v0.1.0 / v1.0.0). Этот номер попадает везде: тег и заголовок релиза, `version` в
`package.json` (Электрон, свойства `.exe`, установщик, имя zip для Яндекса), подпись версии на
заставке игры и `electron/build-tag.json`. Запуски идут по очереди, два одинаковых номера не
выйдут; если тег уже есть — прогон падает сразу. Linux собирается на ubuntu, Windows — на windows-раннере (правка иконки
и версии `.exe` на Linux требует wine). В гит-релиз идут `bird-pizza-deck.tar.gz`,
`install-deck.sh`, `bird-pizza-setup.exe` (установщик для Windows мимо Steam, §8) и
`bird-pizza-win.zip` (папка для депота Windows); отдельно артефактом — zip для Яндекс Игр.

**Сначала надо создать репозиторий релизов** `ndrwbv/bird-delivery` (уже создан; если сменится — поменять константу
`REPO` в `electron/main.cjs` и `tools/install-deck.sh`). Автообновление читает
`/releases/latest` оттуда, установщик качается с `raw.githubusercontent.com/<REPO>/main/tools/`.
Если репозиторий приватный — обновления и `curl | bash` работать не будут.

**Иконки** — пока нет, `.exe` получит иконку Электрона. Положить `build/icon.ico` (256×256)
и `build/icon.png` (512×512): electron-builder подхватит их сам. Для ярлыка на Deck
`install-deck.sh` ищет `resources/icon.png` — добавить в `build.extraResources`
`{ "from": "build/icon.png", "to": "icon.png" }`.

## 2. Steamworks: разово

1. Партнёрский аккаунт <https://partner.steamgames.com>, взнос Steam Direct (сейчас 100 $,
   возвращается после 1000 $ выручки), налоговая форма и банк. Суммы и сроки сверять на сайте.
2. Создать приложение → **App ID**. Положить его в `steam_appid.txt` в корне репозитория
   (только для локального запуска мимо Steam; в депот этот файл **не** класть) или в env
   `STEAM_APP_ID`.
3. **SteamPipe → Depots**: два депота — `<appid>+1` Windows, `<appid>+2` Linux, у каждого своя ОС.
4. **Installation → Launch Options**, по строке на платформу:

   | ОС | Executable | Arguments |
   | --- | --- | --- |
   | Windows | `BirdPizza.exe` | `--steam` |
   | Linux (SteamOS) | `bird-pizza.sh` | `--steam` |

   `--steam` выключает автообновление с GitHub (Steam обновляет сам). Без него оболочка
   определяет Steam по `SteamAppId`/`SteamGameId`, но явный флаг надёжнее.
   Linux-сборка нативная — Proton не нужен, и это плюс к Deck Verified.
5. **Steam Cloud** (App Admin → Cloud): квота ~10 МБ, файлов ~100. Сохранения — это
   localStorage Электрона в `userData` (путь закреплён в `main.cjs`, от productName не зависит).
   Root Overrides по ОС:

   | ОС | корень | подпуть |
   | --- | --- | --- |
   | Windows | `WinAppDataRoaming` | `BirdPizza/Local Storage` |
   | Linux | `LinuxHome` | `.config/BirdPizza/Local Storage` |
   | macOS | `MacAppSupport` | `BirdPizza/Local Storage` |

   Паттерн `*`, рекурсивно. Внутри — LevelDB (несколько файлов), синк работает, но конфликт
   двух машин решается «кто последний», слияния нет. Надёжнее позже писать сохранения одним
   JSON-файлом через steamworks.js `cloud.writeFile` — это TODO.
6. Страница магазина: описание, скриншоты, трейлер, возрастной рейтинг — в игре кровь и
   сбитые прохожие (`features.gore: true`), указать честно.

## 3. Заливка: SteamPipe

Steamworks SDK → `tools/ContentBuilder`. `scripts/app_build.vdf`:

```
"appbuild"
{
  "appid" "<APPID>"
  "desc"  "Bird Pizza <тег>"
  "buildoutput" "..\\output\\"
  "contentroot" "..\\content\\"
  "setlive" ""
  "depots" { "<APPID+1>" "depot_win.vdf"  "<APPID+2>" "depot_linux.vdf" }
}
```

`depot_linux.vdf` (Windows — то же со своим id и папкой):

```
"DepotBuild"
{
  "DepotID" "<APPID+2>"
  "contentroot" "..\\content\\linux\\"
  "FileMapping" { "LocalPath" "*" "DepotPath" "." "recursive" "1" }
  "FileExclusion" "steam_appid.txt"
}
```

В `content/linux/` — содержимое `linux-unpacked/` из `bird-pizza-deck.tar.gz` (вместе с
`bird-pizza.sh`; метки `.github-install` там нет — её ставит только установщик).
В `content/win/` — распакованный `bird-pizza-win.zip`. Дальше:

```bash
steamcmd +login <билд-аккаунт> +run_app_build ../scripts/app_build.vdf +quit
```

Steamworks → **Builds** → выкатить на ветку `beta`, проверить на Windows и Deck, потом `default`.

## 4. Steamworks в игре (steamworks.js)

Подключён **необязательной** зависимостью (`optionalDependencies`, prebuilt под win/linux/mac,
`asarUnpack` в package.json). `main.cjs` грузит его в `try/catch`: нет модуля, нет Steam или
App ID — игра идёт без достижений. Что проброшено в рендерер:

```js
Platform.steam.available                // Steam поднялся
Platform.steam.deck                     // Steam Deck
Platform.steam.achievement('FIRST_ORDER')
Platform.steam.setStat('orders', 42)    // int-статы, сразу store()
Platform.steam.getStat('orders')
Platform.steam.textInput('Имя', 24, '') // экранная клавиатура → строка | null
Platform.steam.leaderboard.upload('BEST_SHIFT', 54000, [17, 3]) // → { ok, rank, prev, changed } | null
Platform.steam.leaderboard.top('BEST_SHIFT', 10)    // места 1…10 → [{ rank, name, score, delivered, level, me }] | null
Platform.steam.leaderboard.friends('BEST_SHIFT')    // друзья в Стиме и ты
Platform.steam.leaderboard.around('BEST_SHIFT', 2)  // ты и по двое сверху/снизу; [] — тебя нет
Platform.shell.info() / checkUpdate(manual) / setFullscreen(on)
```

Ответ `null` у таблиц — Стим не запущен или не ответил: игра берёт локальную таблицу (§4.2).

Язык: выбор игрока (`dlv-lang`) → язык игры в Steam (`apps.currentGameLanguage`) → системный → en.
Имя игрока: `dlv-name`, пока не введено — ник в Steam.

Достижения в игре расставлены (03.10.2026) — список и что завести в Steamworks руками — ниже, §4.1.

### 4.1 Достижения (`src/game/achievements.js`)

**32 достижения.** Игра сама считает всё у себя (сохранение `dlv-ach`: что получено и счётчики за
всё время) и в момент получения зовёт `Platform.steam.achievement(API Name)`. Стим сам показывает
свою всплывашку. Без Стима (браузер, Стим без App ID) — маленькая плашка «достижение · название»
снизу слева на 4 с, клики не ловит. При каждом запуске всё полученное раньше ещё раз уходит в Стим
(если в тот раз Стима не было — догонит). Сброс прогресса в настройках достижения и счётчики **не
стирает** — как и в Стиме.

**Взрослые** (кровь, люди) — только во взрослой версии: в детской счётчик копится, а достижение не
выдаётся; переключил на взрослую — выдастся при следующем таком событии.

**Что сделать руками в Steamworks** (App Admin → Stats & Achievements → Achievements → «New
Achievement» на каждую строку):
1. **API Name** — ровно как в таблице (латиница, заглавные). Опечатка — игра зовёт, а Стим молчит.
2. **Display Name / Description** — ru и en из таблицы (язык выбирается в той же форме; остальные
   языки — потом, одним проходом с переводом игры).
3. **Hidden** — «да» там, где в таблице «скрытое» (в Стиме до получения видно только «скрытое
   достижение»).
4. **Иконки** — по две на каждое: цветная (получено) и серая (не получено), 256×256 JPG/PNG.
   Их надо нарисовать (32 × 2) — заготовка: тот же пиксельный стиль, что у игры.
5. **Stats** заводить не нужно: счётчики живут в игре. Полоску прогресса «47 / 100» в Стиме можно
   добавить потом (int-стат + «Progress stat» у достижения; мост `Platform.steam.setStat` уже есть).
6. Нажать **Publish** (Publish → Prepare for publishing → Publish to Steam), иначе в игре их нет.

Проверить без релиза: в `?debug` — `__dlv.ACH.list()` (все, с прогрессом), `__dlv.ACH.stats()`
(счётчики), `__dlv.ACH.got()`, `__dlv.ACH.unlock('MOOSE')` (выдать руками), `__dlv.ACH.sent` (что
ушло в мост). Стереть у себя в Стиме — `Platform.steam.clearAchievement(id)` (есть в preload);
локально — `__dlv.ACH.wipe()`.

### 4.2 Таблица рекордов «лучшая смена» (`src/game/board.js`, `electron/steamlb.cjs`)

**Что видит игрок.** В меню карьеры (только Стим-сборка) — кнопка «таблица рекордов»: окно
«лучшая смена» с вкладками **«весь мир»** (места 1—10; тебя в десятке нет — после «…» твоя строка
с местом) и **«друзья»** (друзья из Стима, кто играл, и ты; места — общие). Внизу — «ты — N-й,
сумма». Стим не запущен или не ответил за 15 с — вкладок нет, «лучшие смены на этом компьютере»
(локальная таблица, как раньше). В web и Яндексе — всё как было.

**Что пишется.** В конце каждой смены карьеры — заработок смены (как его видит игрок, ₽) и к нему
две цифры «подробностей»: сколько заказов и уровень курьера. Стим хранит **лучшую** смену игрока
(худшая не перезаписывает). На экране итогов строка: «смена в таблице рекордов · ты #N в мире»,
побил свой рекорд — «лучшая смена! ты #N в мире». Не пишется: смена без заработка, «покататься»,
проверочные прогоны (`?nolb`). Копия всегда уходит и в локальную таблицу этого компьютера.

**Как устроено.** steamworks.js таблиц не умеет (последний выпуск — август 2024, заявки на таблицы не приняты).
Варианты, что смотрели (октябрь 2026):

| вариант | что | почему нет / да |
|---|---|---|
| steamworks-ffi-node 0.11 | живая, ~16 тыс. скачиваний в месяц, таблицы есть | целиком заменяет steamworks.js (достижения, клавиатура, оверлей — всё переписывать и заново проверять), библиотеку Стима не возит — SDK качать руками, требует Node 22 (у Электрона 33 — Node 20), у оверлея открытые баги на Linux |
| greenworks | старая, 72 скачивания в месяц | заброшена, сборка под каждый Электрон |
| форк steamworks.js | заявки #198, #208 не приняты, готовых сборок нет | собирать Rust под три системы самим |
| **своя надстройка на koffi** | koffi 3.3 — FFI, ~17 млн скачиваний в месяц, MIT, готовые сборки под все системы, без компиляции | **выбрано**: ~200 строк, steamworks.js и всё, что на нём, не трогаем |

`electron/steamlb.cjs` через koffi зовёт функции таблиц прямо в `steam_api` — в ту же библиотеку,
что привёз и уже поднял steamworks.js (`node_modules/steamworks.js/dist/<система>/`). Тонкость:
steamworks.js 30 раз в секунду сам разбирает очередь ответов Стима и чужие ответы выбрасывает.
Поэтому `main.cjs` ловит его таймер и, пока таблица ждёт ответа, очередь разбирает `steamlb.cjs`
(тем же порядком вызовов), в остальное время — steamworks.js, как раньше. Пока открыта экранная
клавиатура Стима (её ответ ждёт steamworks.js), очередь не трогаем. Таблица заводится сама при
первом вызове (`FindOrCreateLeaderboard`: по убыванию, число), но лучше завести руками — ниже.
koffi — необязательная зависимость, как steamworks.js; в сборке лежит распакованным (`asarUnpack`).
Не поднялось (нет koffi, нет Стима) — `lb: false` в мосте, игра на локальной таблице. Выключить
руками — флаг запуска `--no-steam-lb`. С `--log` в консоли видно `lb: таблицы Стима готовы` или причину.

**Что сделать руками в Steamworks** (App Admin → Stats & Achievements → **Leaderboards** → «New Leaderboard»):

| поле | значение |
|---|---|
| Name (API) | `BEST_SHIFT` — ровно так, латиница |
| Community Name | ru: «Лучшая смена», en: «Best Shift» |
| Sort Method | **Descending** (больше — выше) |
| Display Type | **Numeric** |
| Writes | галку «Trusted» **не** ставить — пишет сама игра (Trusted — только с сервера через Web API) |
| Reads | читать могут все (не «только друзья» и не «только свои») |

Потом **Publish** (как у достижений), иначе в игре таблицы нет. Одна таблица на всё — без «за
неделю»: Стим сам не обнуляет, сезоны — потом отдельными таблицами, если понадобятся.

**Как проверить на настоящем Стиме** (нужен App ID и Стим, запущенный под аккаунтом с игрой):
1. `npm run electron -- --windowed --log --steam` → в консоли `steam: ок` и `lb: таблицы Стима готовы`.
2. Отработать смену с заработком → на итогах «смена в таблице рекордов · ты #1 в мире».
3. Меню → «таблица рекордов»: «весь мир» — твоя строка с ником из Стима; «друзья» — ты (и друзья,
   если играли). В Steamworks → Leaderboards → «View entries» — та же запись.
4. Худшая смена → место не меняется; лучшая → «лучшая смена! ты #N в мире».
5. Выйти из Стима и запустить снова → окно без вкладок, «лучшие смены на этом компьютере».
6. Открыть экранную клавиатуру Стима (имя в настройках на Deck) — должна работать как раньше.
Если что-то не так — запустить с `--no-steam-lb` (игра как до таблиц) и прислать вывод `--log`.

**Без Стима (probe):** `npm run probe -- --mode=steam --q=mock-steam --eval=…` — подделка моста
`src/platform/steam-mock.js` (30 игроков в мире, трое — друзья; все вызовы — в
`window.__steamMock.calls`); `--q=mock-steam=fail` — Стим не отвечает, `=nolb` — таблиц нет.
В `?debug`: `__dlv.BOARD.open()`, `__dlv.Platform.leaderboard.top(10)`.

**Game Center (iOS, [IOS.md](IOS.md)):** то же самое — App Store Connect → приложение → Game Center →
Leaderboards → «Classic Leaderboard»: **Leaderboard ID** `BEST_SHIFT` (можно `birdpizza.BEST_SHIFT`),
Score Format — Integer, Sort — High to Low, Score Range — от 1, «Submission type» — Best Score;
ru/en название «Лучшая смена» / «Best Shift». В игре — тот же мост: в `steam.js` вместо
`bridge.steam.lbUpload/lbEntries` для iOS — плагин Capacitor Game Connect (`submitScore`,
`showLeaderboard` — у Game Center своё окно таблицы с вкладками «все / друзья»; своё окно на iOS можно
не рисовать, кнопка просто открывает окно Game Center).

## 5. Steam Deck Verified — что проверить

* **Только контроллер.** Вся игра — заставка, выбор машины, магазин, пауза, обед, карточки
  клиентов, карта — проходится с геймпада (`src/input/gamepad.js` + `padmenu.js`).
  Подсветка выбранного пункта — класс `.padsel`. Нигде не требуется тач или мышь.
* **Глифы.** Подсказки на экране при игре с геймпада должны показывать кнопки геймпада,
  а не `W`/`Shift`/`Tab` (гайд `#guide` — сейчас клавиатура и тач). TODO.
* **Текст при 1280×800.** Минимум ~9 px по высоте строчной буквы на экране Deck'а. Проверить
  адреса в HUD (`#addr`), реплики в карточке выбора, строки таблицы, подписи магазина.
* **Экранная клавиатура для имени.** Поле `#st-name`: по A вызывать
  `Platform.steam.textInput('Как тебя зовут', 24, текущее)` и подставить результат. Если
  вернулось `null` (не Big Picture / нет Steam) — либо фокус в поле (Steam сам поднимет
  клавиатуру по STEAM+X), либо на Deck брать ник из Steam и не спрашивать имя вовсе
  (`Platform.player.name` уже так и делает, пока `dlv-name` пуст).
* **Раскладка по умолчанию.** Опубликовать официальную Steam Input-раскладку «Gamepad»;
  без неё сторонняя раскладка «Gamepad with Mouse Trackpad» тоже работает.
* **Пауза при выходе в меню Steam** — `onPause` срабатывает на blur окна и скрытие вкладки.
* **Производительность:** 60 fps при 1280×800 на Deck, иначе — понижать pixel ratio.
* **Выход:** есть `Platform.quit()` (`features.quit`) — кнопка «выйти из игры» в меню.

## 6. Чего Electron не умеет

* **Оверлей Steam** (Shift+Tab) с Chromium обычно не работает: оверлей хукает графику в
  процессе игры, а Electron рисует в отдельном GPU-процессе. Нет оверлея — нет скриншотов
  Steam, браузера и приглашений поверх игры. `--steam-overlay` пробует
  `electronEnableSteamOverlay()` из steamworks.js (in-process-gpu + перерисовка каждый кадр) —
  на Windows иногда помогает, может стоить fps. Для Verified оверлей не обязателен.
  `showGamepadTextInput` работает без оверлея только в Big Picture / на Deck.
* **Steam Input** работает: Deck и любые геймпады приходят через Gamepad API.

## 8. Установка на Deck и Windows мимо Steam (тестеры)

Для игрока целиком (ярлыки, обновление, запуск из игрового режима) — в [README](../README.md#steam-deck-и-windows-поставить-обновить-играть); этот же текст CI кладёт в описание каждого релиза.

В Konsole (десктоп-режим):

```bash
curl -fsSL https://raw.githubusercontent.com/ndrwbv/bird-delivery/main/tools/install-deck.sh | bash
```

Игра встанет в `./bird-pizza`, ярлык «Птица Пицца» появится в меню; в Steam — Add a Non-Steam
Game → `bird-pizza.sh`, Proton не включать. Такая установка сама предлагает обновления
(метка `.github-install`, тег из `electron/build-tag.json` против последнего релиза).
Сохранения — `~/.config/BirdPizza`, обновление их не трогает.

**Windows** — `bird-pizza-setup.exe` из релиза: установщик NSIS (electron-builder, настройки —
`build.nsis` в `package.json`), ставит в профиль без прав админа
(`%LOCALAPPDATA%\Programs\bird-pizza-delivery` — папка по `name` из `package.json`), ярлыки
«Птица Пицца» на рабочем столе и в «Пуске», запись в «Приложениях» для удаления. Не подписан —
SmartScreen спрашивает «Подробнее → Выполнить в любом случае». Признак такой установки для игры —
`Uninstall BirdPizza.exe` рядом с `BirdPizza.exe` (в zip для Steam его нет). Обновление: игра
качает свежий `bird-pizza-setup.exe` (адрес из `/releases/latest`) во временную папку, закрывается
и запускает его с `--updated --force-run` — он встаёт поверх и запускает игру. Сохранения —
`%APPDATA%\BirdPizza`, ни обновление, ни удаление их не трогают (`deleteAppDataOnUninstall: false`).
Депот Windows в Steam по-прежнему из `bird-pizza-win.zip`: установщик туда не кладём.

## Производительность на Steam Deck

Цель — 60 fps **ровно**, а не «в среднем». Замер без Деки — `tools/perf.cjs --deck`: экран
1280×800 и процессор втрое медленнее (DevTools CPU throttling; Zen 2 против Apple M — примерно
так). Видеокарту так не замедлить, но она не узкое место: картинка рисуется в 540 точек по
короткой стороне и растягивается, а вызовов отрисовки — 150–650 за кадр.

```bash
npm run build:web
npx electron tools/perf.cjs --deck                    # Северск, лето, день
npx electron tools/perf.cjs --deck "--q=&season=2.4"  # зима
npx electron tools/perf.cjs --deck --fps=40           # как с ограничением 40 fps в Steam
npx vite build --mode web --outDir dist/dbg --minify false
npx electron tools/perf.cjs --deck --spikes --dist=dbg   # что делали самые долгие кадры
```

Средний fps плавность не показывает: 58 кадров в секунду с парой кадров по 40 мс — это рывки.
Поэтому perf печатает раскладку: медиана, p95, p99, худший кадр, сколько кадров длиннее 20 и
33 мс, и «JS» — сколько из кадра занял сам код игры. На Деке экран 60 Гц: кадр, где код дольше
16,7 мс, опаздывает к развёртке и показывается дважды — счётчик fps почти не меняется, а глаз
видит подёргивание. Это и было «fps правильный, а не плавно».

Что сделано (`src/game/cull.js`):

- неподвижная статика — `matrixAutoUpdate = false`, куски города дальше края камеры снимаются
  со сцены, реквизит заморожен, пока не падает;
- **матрицы сцены считает `CULL.step()`, а не рендер.** three.js r169 сам пересобирал матрицу
  сцены каждый кадр и тем заставлял пересчитать все ~7 тысяч объектов — и замороженные, и
  спрятанные. Теперь считаются только видимые и движущиеся (~2 тысячи); стоящие лёгкие машины у
  бордюров и перекрытия районов (сотни деталей) — один раз;
- шейдеры компилируются под экраном загрузки (`renderer.compile`), без рывка при первом появлении;
- страховка дальности (туман и край камеры ступенями 1 → 0,85 → 0,72, если кадр в среднем
  длиннее 18,5 мс две секунды) больше не качается: раньше на грани она каждые ~15 с опускалась
  и поднималась (в модели — 71 переключение за 10 минут, каждое с рывком и скачком тумана),
  теперь неудачная попытка подняться удваивает ожидание (12 → 24 → … → 240 с; 11 переключений
  за 10 минут), дальность меняется плавно за ~1,5 с, а если код занял меньше половины кадра
  (стоит ограничение 40/45 fps или экран на 50 Гц) — дальность не режется. Раньше при
  ограничении 40 fps она падала до 0,72 даже на быстром железе.

Замеры (2.10.2026, Северск, `--deck`, шесть точек по 4 с; цифры между прогонами гуляют на
10–20 %, на машине одновременно шли другие замеры):

| | было | стало |
|---|---|---|
| код игры за кадр, медиана | 12–12,5 мс | 9,6–11,3 мс |
| код игры за кадр, p99 | 19–22 мс | 17,6–17,8 мс |
| то же без замедления (Mac), медиана | ~4,5 мс | ~3,7–4,3 мс |
| переключений страховки за 10 мин «на грани» (модель) | 71 | 11 |
| ограничение 40 fps: дальность | падала до 0,72 | остаётся 1 |

**Загрузка.** Город строится целиком при импорте `game.js` (и заново при смене языка — страница
перезагружается). Ускорено без изменения картинки: склейка пишет треугольники сразу в клетки
(без промежуточного массива на сотни мегабайт), цвета по строке разбираются один раз, коробки
`box()` собираются без `BoxGeometry`, ближайшая дорога, дома, заборы, зебры, бордюры — по сеткам
вместо перебора, клетки поднятого тротуара — битовая карта. Город проверен отпечатком: при
одинаковом `Math.random` все загрузки в видеокарту и все геометрии сцены совпадают до бита
(Северск — лето и зима, Москва). Экран загрузки во время сборки анимируется (анимация на
стороне композитора), так что дробить сборку на части не нужно.

| загрузка до заставки | было | стало |
|---|---|---|
| Mac | 4,6 с | 2,8 с |
| процессор втрое медленнее («Дека») | 12,1–12,5 с | 7,1–7,2 с |

**Что проверить на самой Деке.** Включить в Steam оверлей производительности уровня 3–4
(график времени кадра): ровная линия на 16,7 мс — хорошо, зубцы — рывки. `?debug` →
`__dlv.CULL`: ступень дальности (`q`), сколько переключений (`switches`). Если график рваный при
60 fps, а код укладывается, — виноват такт кадров Chromium под gamescope; проба: в параметрах
запуска Steam `%command% --no-vsync` (кадры без ожидания развёртки, показывает их gamescope;
ест больше батареи — по умолчанию выключено).
