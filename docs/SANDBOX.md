# Песочница: проверка механик

```
npm run sandbox          # dev-сервер и сразу /sandbox.html
```

`sandbox.html` — отдельная страница: игра в iframe (`index.html?debug&sandbox&map=…`), справа —
панель ручек. Ручки работают через `window.__dlv` игры (он есть только с `?debug` и в dev).
Собирается в `web` и `steam` (`vite.config.js`, `rollupOptions.input`), в `yandex` её нет.

Код — [`src/sandbox/sandbox.js`](../src/sandbox/sandbox.js), стили — `sandbox.css`. Страница
игровых модулей не импортирует: только данные (`orders.config.js`, `econ.js`), всё остальное —
через `__dlv` внутри iframe.

## Что есть на панели

- **Пресеты** — сценарии в один клик: всё настроить и сразу в ситуацию. Это массив `PRESETS`
  в `sandbox.js`: `{ group, name, needs, want, run }`. `needs` — без этих хуков кнопка серая,
  `want` — желательно (без них пресет идёт упрощённо и пишет об этом в журнал). Новый пресет —
  строка в массиве; помощники — объект `G` (`G.onShift()`, `G.time(h)`, `G.tp(точка)`, `G.story(id, глава)`…).
- **Читы** — «бесконечное здоровье», «бесконечное нитро», «не глохнет». Хранятся в localStorage
  песочницы (`sbx-state`) и заново включаются после каждой перезагрузки игры и каждого пресета.
- **Игра** — карта (Северск / Москва), детская версия (`?kids`), быстрая смена (`?fastshift`),
  звук (`?mute`) — всё с перезагрузкой iframe; начать смену, покататься, принять заказ.
- **Время и погода** — час 9—24 (`ENV.t = ECON.tOfHour(h)`), сезон 0—4 (`__dlv.season.set`), дождь,
  снег (зима + осадки), ясно.
- **Сюжет** — главы историй из `story.js`: «как заказ» (через `orders.force`) и «катсцена» (сразу,
  машина встаёт у подъезда); пропустить катсцену, сбросить прогресс.
- **Районы и волны** — выбрать район 1—8 и сразу смена там («работать тут» открывает все районы),
  открыть все районы, сбросить районы, волна «щедрая / обычная / час пик» (кофе раскладывается сразу,
  заказы — со следующего).
- **Заказы** — срочный, в конец района, развоз смены, любое поручение из `SIDE_ORDERS`.
- **Смена и события** — обед, полночь, итоги смены, заглохнуть, бандиты.
- **Машина** — выбрать любую из `CAR_LIST`, износ мотора (мотор = 100 − 10·L %), открыть все, улица с ямами.
- **Деньги и звёзды**, **донаты** 0—100 %.
- **Телепорт** — пиццерия (где работаешь) и пиццерии других районов, гараж Дяди Жени, особняки, бандитские районы, конец города, дом бабы Зины.

Внизу — журнал: что сделали, каких хуков не хватило, ошибки.

## Хуки

Песочница ищет каждую ручку так: `__dlv.HOOKS[ключ]` (ведущий может подключить что угодно, не
трогая модули) → функция в объекте модуля на `__dlv` → своя реализация на том, что уже отдаёт
game.js. Нет ни того, ни другого — кнопка серая, в подсказке написано, чего не хватает.

Объекты модулей на `__dlv`:

| модуль | где | статус |
|---|---|---|
| career.js | `__dlv.CAREERM` | сам кладёт при `init` |
| orders.js | `__dlv.ORD` | сам кладёт в `step` |
| world.js | `__dlv.WORLD` | **надо подключить**: `__dlv.WORLD = WORLD.DEBUG` (или модуль) |
| cars.js | `__dlv.CARSM` | **надо подключить**: `__dlv.CARSM = CARS` (сам модуль: `select`, `worsen`, `L`, `stallNow`, `potholes`) |
| story.js | `__dlv.STORY`, `__dlv.STORY_DBG` | есть (game.js) |
| seasons.js | `__dlv.season` | есть |

Любой из них можно подключить и без правки модулей: `__dlv.HOOKS = { forceOrder: spec => … }`.

## Сюжет: как story.js встроен

- `STORY.init(api)` — game.js после сборки города; `STORY.frame(dt, car)` — в начале кадра:
  идёт катсцена — рисуем только актёров и камеру, мир стоит (как в диалоге), шарф на машине.
- `STORY.nextOrder(ctx)` зовёт orders.js перед каждой обычной пиццей; номер смены берётся из
  `ctx.shift`, иначе из сохранения `dlv-shifts` + 1. Условия главы: `STORY_PEOPLE` (`fromShift`,
  `every`) и у главы `hours`, `minShift`.
- `STORY.onDeliver(order)` — orders.js, когда заказ отдан (принимает и свою спецификацию, и `S.order`
  со спецификацией в `order.ord.story`). Прохожего, которого orders.js переодел в бабу Зину, на
  время катсцены прячем, потом он уходит в другой квартал другим человеком (`retirePed`).
  Награда — `ECON.ORDERS.STORY_STARS` через `addStars` (career.js) и деньги главы.
- Прогресс — сохранение `dlv-story`: `{ zina: { ch, last, at, scarf } }`. После 3-й главы на машине
  шарф (`STORY.decorate(car)` — сам вешается на любую новую машину). Ширина шарфа — по кузову
  машины (с зеркалами, не шире 2,6 м): всё, что висит на машине сверх неё, — крылья и сияние
  оживления (`userData.noBox`), спрятанное и прозрачное (тень) — не меряется.
- Esc или «пропустить» — сразу к награде (шарф всё равно вяжется).

### Как добавить экран

Экран — объект в массиве, который возвращает файл в `src/uilab/screens/` (подключение — `lab.js`,
строка `SCREENS`):

```js
{ id: 'lunch', group: 'Окна поверх езды', name: 'обед', note: 'что проверять',
  knobs: [{ k: 'n', label: 'сколько блюд', type: 'num', def: 3, min: 1, max: 5, step: 1 }],   // num | bool | sel | text
  auto: true,                       // false — показывать только по кнопке (как диалоги)
  async show (o, tok) { … }         // o — значения ручек; tok.dead — экран уже сменили
}
```

В `ctx` (аргумент файла экранов) — `A` (заглушка api), `Store`, `t`, `tn`, `money`, `log(текст)`,
`$`, `sleep`, модули игры (`CM` — отладка career.js, `END`, `CHAT`, `DLG`, `DIST`, `ECON`, `ORD`),
`makePerson`, `faceDataURL`; `ctx.cleanup = () => …` — убрать за собой при смене экрана.
Панель подхватывает новый экран сама.

### Как добавить мини-игру (блок 13)

Файл в `src/game/minigames/<имя>.js` (или `src/uilab/minigames/` — для примеров) с
`export default { id, name, note, knobs, mount(root, o, api) → убрать }` — и в разделе
«Мини-игры» сразу появляется кнопка (`src/uilab/minigames.js` собирает обе папки сам).
`mount` рисует игру в `root` (на весь экран поверх игры); `api`: `t`, `tn`, `money`, `ADULT`,
`log(текст)`, `done(итог)` — игра кончилась (итог — в журнал), `makePerson`, `faceDataURL`.
Образец — `src/uilab/minigames/example.js` (домофон-заглушка: набрать номер квартиры).

## Редактор города: `editor.html` (09.10.2026)

Весь город без езды: летать, ставить пометки «тут кривое / тут сделать», ставить и убирать

```
npm run editor           # dev-сервер и сразу /editor.html (порт 5195)
```

Город строит сама игра (тот же `main.js` → `game.js`, тот же сбор города): страница берёт разметку
из `index.html`, ставит `window.__EDITOR` и грузит игру. Меню и хад спрятаны, клавиатура, мышь и
геймпад игре не достаются, камеру в кадре меню ставит редактор (`game.js` зовёт
`__dlv.EDL.ED.cam`). Пока город достраивается — надпись «город строится…» (несколько секунд).

### Кнопки

| что | как |
|---|---|
| лететь | **W A S D** / стрелки; **Q / E** — ниже / выше; **Shift** — втрое быстрее (скорость растёт с высотой) |
| повернуть голову | зажать и тянуть мышью (левой или правой кнопкой) |
| высота | колесо мыши |
| геймпад | левый стик — лететь, правый — смотреть, курки — ниже / выше, LB / RB — медленнее / быстрее, A — действие в центре экрана (там крестик), B — отмена |
| виды | «сверху» и «сбоку» — на точку в середине экрана; «к пиццерии»; «к точке» — x и z в метрах карты; клик по мини-карте — туда же («рядом» / «весь город» — масштаб карты) |
| дальность | «как в игре» / «далеко» (1,6 км) / «весь город» (6 км): туман и край камеры дальше |
| время, сезон | 9—23 ч; лето, осень, зима, весна — посмотреть, как правка выглядит в снегу и ночью |
| инструменты | **1** смотреть · **2** пометка · **3** поставить · **4** выбрать / убрать; **R** — повернуть предмет на 15°, **Del** — убрать выбранное, **Esc** — отмена |

- **Пометка:** клик по городу → текст → Enter. Булавка (красная; сделано — зелёная) с подписью над
  ней, список справа: галочка «сделано», → лететь, ✎ править текст, × удалить, «прятать сделанные».
- **Поставить:** палитра — деревья (берёза, сосна, ель, тополь, клён, липа, рябина), кусты (куст,
  сирень, шиповник), улица (лавочка, четыре фонаря, урна), мелочь газона (клумба из покрышек, куча
  песка, выбивалка), постройки-коробки (сарай, ларёк, гараж, коробка; ширина, глубина, высота, цвет).
  Под мышью — заготовка; **красная** — тут плохо: дерево ближе 2,5 м к дороге, в воде или в доме
  (игра его не посадит), лавочка на дороге или у стены, коробка на асфальте (упадёт `npm run check`,
  «постройки не на дороге»). Клик по плохому месту спрашивает «поставить всё равно?».
- **Выбрать / убрать:** клик по предмету. Свой (поставленный в редакторе, синее кольцо) — повернуть
  или убрать. Городской — убрать: дерево и куст, лавочка, фонарь, урна, куст у дорожки, заборчик,
  песочница, горка. Убранное помечено красным крестом.
- **Пересобрать город** — страница перезагружается (камера остаётся на месте), игра строит город с
  правками. До этого поставленное видно заготовкой, а убранное — ещё стоит, с крестом. Список правок
  пишет у каждой: «ещё не в городе», «в городе / убрано», красным — «игра не поставила» или «тут
  ничего не нашлось».

### Файлы — в репозитории, их читают агенты

Сохраняется само, через секунду после клика (dev-сервер, `vite.config.js` → `editorFiles`:
`GET/POST /__editor/file?map=seversk&f=notes|edits`). Запись файла страницы не перезагружает.
Одна пометка или правка — одна строка.

- **`src/maps/seversk/notes.json` — пометки:**
  `{"id":"n…","x":3150.2,"z":2081.7,"text":"тут дерево в стене","date":"2026-10-09","done":false}`.
  x и z — метры карты (как `__dlv.V.x/z`, телепорт в песочнице, `geo()` в `index.js`). Игра файл не
  читает. **Агенту:** прочитать файл, открытые — `done: false`; посмотреть место —
  `npm run probe -- --page=editor.html --js="__editor.goTo(x, z, 40); await wait(1500)" --shot=…`
  (или `__editor.top(x, z)`, `__editor.side(x, z)`); сделал — поставить `done: true` и дописать в
  `text`, что сделано (« → сделано: …»). Не удалять — удаляет автор.
- **`src/maps/seversk/edits.json` — правки предметов:** `add` — что поставить
  (`{"id","kind","sub","x","z","ry"[,"w","d","h","col"]}`), `remove` — что убрать (`{"kind","x","z"}`).
  Игра применяет при сборке города — `src/game/editlayer.js` (кусок поздней сборки `edits`, после
  деревьев дворов): поставленное — теми же функциями, что и город (дерево — `tree` с породой, лавочка —
  `bench`, фонарь — `streetlamps.js`, остальное — сбиваемое, коробка — статика и твёрдый
  прямоугольник); убранное — предмет этого вида ближе 0,35 м к точке. Править руками можно — тем
  же форматом.

### Почему «убрать вот это» попадает в то же самое

Деревья вдоль улиц, лавочки в парках, урны у подъездов и многое другое ставились по `Math.random` —
каждый запуск в другом месте. Теперь город (всё, что строит `game.js` до меню, и куски поздней
сборки, которые ставят город, — `editlayer.js SEEDED`) строится **с зерном**: одинаковый каждый
запуск, в редакторе и в игре. После сборки `Math.random` снова обычный — машины, люди, заказы,
находки случайные, как были. Убранное вынимается **после** сборки, а не «не ставится»: иначе
пропажа одной лавочки сдвигает жребий у соседей. Проверено probe: два запуска — все ~8,6 тыс.
деревьев и ~12 тыс. сбиваемых на тех же местах; с правками отличаются ровно правки.

Оговорка: город тот же при той же игре. Поменяли код сборки (новый кусок, другой порядок) или карту
— часть случайного сдвинется, и старое «убрать» может ничего не найти: список правок и
`npm run check` об этом скажут («тут ничего не нашлось»), такую правку автор ставит заново.
Кусок поздней сборки, который ставит город, — добавить в `SEEDED`.

### Проверка

`npm run check` — «правки редактора применены» (`tools/probe-checks/edits.js`: поставленное стоит,
убранного нет; «игра не поставила» и «ничего не нашлось» — предупреждение), коробки из редактора —
в «постройки не на дороге». Без браузера — probe:

```
npm run probe -- --page=editor.html --size=1400x850 --js="__editor.goTo(3175, 2095, 45); await wait(1500)" --shot=out.png --scale=0.6
npm run probe -- --page=editor.html --js="return __editor.check({ kind: 'box', sub: 'kiosk', x: 3164, z: 2060, ry: 0 })"
npm run probe -- --js="return d.EDL.STATS"     # игра: сколько убрано по видам, что не встало
```

`window.__editor`: `st` (пометки, правки, инструмент), `cam`, `goTo(x, z, h)`, `top(x, z)`,
`side(x, z)`, `setTool('look|note|place|pick')`, `setKind('берёза')`, `addNote(x, z, текст)`,
`place({ kind, sub, x, z, ry })`, `removeCity(kind, x, z)`, `check(правка)`, `pickAt(экранX, экранY)`,
`cityNear(x, z, r)`. В сборке для probe сохранять нельзя (нет dev-сервера) — правки только в памяти.

Код: `editor.html` → `src/editor/main.js` (вход), `editor.js` (панель, инструменты), `cam.js`
(камера), `minimap.js`, `files.js` (чтение и запись); в игре — `src/game/editlayer.js` и точечные
хуки в `game.js` (tree, smashAdd, кусок `edits`, камера меню, геймпад, кадр меню) и `streetlamps.js`
(`unlamp`).

## Дальше: редактор карты (план; v1 — «Редактор города» выше)

Сделано в `editor.html`: свободная камера, метки «тут кривое» (`notes.json`), предметы — поставить,
повернуть, убрать (`edits.json`). Дальше — дома (`overrides.json`) и точки сюжета.

Главная боль: карту нельзя удобно править и наполнять, поэтому контент добавляется медленно.
Решение — редактор внутри игры, а не переезд на движок с редактором сцен (почему —
[DIRECTION.md](DIRECTION.md), «Решения»). Объём — несколько дней, основа (`__dlv`, телепорт,
песочница) уже есть.

### Как правится карта сейчас

| что | где | как поменять |
|---|---|---|
| дома | `src/maps/seversk/city-data.js` из `scripts/osm_seversk.py` | `overrides.json` по OSM id (`lv`, `st`, `col`, `roof`, `h`, `{"drop": 1}`…), потом `python3 scripts/osm_seversk.py build` — вслепую, id надо искать |
| забор, КПП, рельсы, крыши, вывески ТЦ | `src/game/citybits.js` из данных карты | только кодом |
| АЗС, каток | `src/game/landmarks.js` из данных карты | только кодом |
| мелкие объекты, точки сюжета и поручений | код модулей | только кодом |

То есть «поставить сюда ларёк» — это правка кода или json без картинки перед глазами.

### Что должен уметь (v1)

- **Режим `?edit`** (кнопка в песочнице): свободная камера — облёт и вид сверху, игра на паузе.
- **Дома:** клик по дому → его OSM id и поля; менять этажность, стиль, цвет, крышу, удалить.
  Пишется в `overrides.json` — тот же формат, что руками.
- **Объекты:** палитра (ларёк, киоск, лавка, урна, гаражи, припаркованная машина, табличка с
  текстом, точка для людей) — поставить, подвинуть, повернуть, удалить. Новый файл
  `src/maps/<id>/props.json`, игра читает его при загрузке.
- **Метки «тут кривое»:** клик → точка и заметка (текстура легла криво, провал, застревает).
  Файл `bugs.json` — готовый список на неделю полировки.
- **Сохранение только в dev:** POST на `vite`-middleware (`vite.config.js`), он пишет json в
  `src/maps/<id>/`. В сборки не попадает, как и сама песочница в `yandex`.
- Правки домов видны сразу: `overrides.json` применяется ещё и на лету при загрузке, чтобы не
  гонять `build` после каждого клика (`build` остаётся для окончательной сборки данных).
